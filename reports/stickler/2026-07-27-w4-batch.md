## FINDINGS

### F1 (HIGH) — the rpg state round bypasses the D17 consent belt AND the room's assigned connection

`packages/server/src/entry/compose/rpg.ts:221` (`buildRunExtraction`), `:394` (`buildRunToolRound`), and the
hard-coded `ownerConsented: true` at `:134` and `:413`.

**Defect.** Both dedicated state rounds resolve the model call via
`deps.connection.resolveRole({ role: "chat", principal: host })` — the host's **global
`routing.roleDefaults.chat`** — and stamp `ownerConsented: true` unconditionally. The real narration turn
resolves the **room's** connection (`connection.resolveChat({ routableChat })`, `entry/compose/chat.ts:467-471`
— `RouteChatAssignment` is "the chat row's routing fields", `packages/contracts/src/connection/index.ts:273`)
and derives consent through `assertMaxProSubConsent`/`resolveOwnerConsented`
(`domain/chat/engine/engine.ts:987-997`, `engine/turn-identity.ts:47-57` — "fail-closed, default OFF").
Neither `resolveTurnPolicy` nor `allowNonOwnerMaxProSub` is ever read on the rpg path.

**Failure scenario (consent bypass).** Host = the box OWNER; owner's `roleDefaults.chat` is UNSET, so the
selector default resolves `max-pro-sub`/`agent-sdk` (`domain/connection/verbs/resolve-role.ts:44-49` — the
owner-conditional default); the game ROOM is assigned to vllm/OpenRouter (so non-owner member turns pass the
consent belt); `allowNonOwnerMaxProSub` = false (the D17 default). Every MEMBER-triggered committed game turn
then fires an extraction/tool-round call on the owner's metered sub with consent force-stamped `true` — the
exact by-proxy spend class `assertMaxProSubConsent` exists to refuse. Ban-risk + billing on the owner's sub,
driveable by any member message.

**Failure scenario (wrong connection).** Even solo: a game room assigned (per-chat routing) to local vllm
while the owner's global default is the sub runs its per-turn state round on the SUB, not the room's engine —
and `buildResolveTrackersReadOnly` (`compose/rpg.ts:486-500`) keys the capability verdict on the same wrong
connection, so the readonly pill can contradict the room's actual model.

**Evidence (this session).** Read of compose/rpg.ts in full; `grep ownerConsented` across domain/chat +
entry (the only two `true` literals are the rpg compose ones); resolve-role.ts owner-default arm; engine.ts
987-997; turn-identity.ts read in full; contracts RouteChatAssignment. No test pins consent on this path (the
composed-real tests fake `resolveRole`, so both arms resolve identically — the divergence is untestable
there by construction).

**Doctrine.** D17 ("hosted credentials… non-owner use requires explicit consent, default OFF");
D108(3) says the host resolves by role — it does not sanction ignoring the room's connection assignment;
Tier-3b invariant 5/§7.1 (the firewall re-verifies what the DOMAIN derives — here nothing derived it).

**Remediation direction (safe).** Resolve the state round's connection through the same
`resolveChat({routableChat})` seam the narration turn uses, and derive `ownerConsented` from
`resolveTurnPolicy(host)` + the triggering identity instead of a literal `true`. Regression test: a fake
policy with `allowNonOwnerMaxProSub:false` + a member-triggered flush on a sub-default host must NOT reach the
executor with a max-pro-sub credential.

### F2 (MEDIUM) — the dedicated state round fires even when the game is readonly/manual-steering

`packages/server/src/domain/rpg/chat-ops/index.ts:61-73` → `chat-ops/flush.ts:123-132` →
`entry/compose/rpg.ts:213-275, 384-428`.

**Defect.** Nothing on the flush path consults the capability verdict. `onTurnCompleted` → `flushTurn` →
`stageStateRound` → `runExtraction`/`runToolRound` runs unconditionally for every committed game turn. The
batch's own law-comments claim otherwise: gather.ts:11-12 ("readonly/manual-steering — **NO state round**"),
compose/rpg.ts:19 ("A game whose model has no structured-output writer capability **never reaches here**"),
compose/rpg.ts:383 ("A game whose model has no `tools` capability never reaches here"). `deriveTrackersReadOnly`
(`substrate/readonly-axis.ts`) is consumed only by the UI pill + the reminder — never by the flush.

**Failure scenario.** A lite game whose host connection lacks `output.structured` (reliable) or `tools`
(cheap): every turn still pays a full extra model call that predictably fails (`rpg.extraction.failed` /
`rpg.extraction.unparseable` / `rpg.toolround.failed` per turn), plus barrier wait time. On hosted credentials
that is real recurring spend for a structurally impossible write.

**Evidence.** Read of all three files in full; grep for `resolveTrackersReadOnly`/`deriveTrackersReadOnly`
consumers (gather, tracker-view, get-game, compose only); no readonly pin in flush.int.test (grep shown in
log). The E2E rounds all ran capability-positive models, so this never surfaced.

**Doctrine.** The honest-arms posture itself (D86/D108 "capability ABSENT → warn + manual-steering") — the
code's headers state the gate; the gate does not exist. A header that is per-domain law contradicting the
implementation is itself a defect.

### F3 (MEDIUM) — nudge-tail turns put the depth-0 system reminder BARE into the agent-sdk user prompt

`packages/server/src/entry/compose/chat.ts:111-125` (`extractTrailingSystemRows`) vs
`packages/server/src/domain/chat/assembly/shape.ts:210-218`.

**Defect.** `extractTrailingSystemRows`'s docstring claims "System rows are tail-only by construction … so a
trailing-run scan is total." False: `shape()` appends the group-nudge / `CONTINUATION_NUDGE` user tail AFTER
the spliced depth-0 system row (`history = runSquash([...named, {role:"user", content: tailUser}])`), producing
`[..., assistant, system, user]`. This exact shape is pinned by the batch's own new test
("capable + no user tail on an assistant-final canon: the CONTINUATION_NUDGE still lands (ends-on-user reads
past system rows)", tests/server/domain/chat/assembly/shape.test.ts). On that shape the trailing-run scan finds
`user` and extracts nothing; `splitAgentHistory` then puts the system row in the prompt TAIL:
`prompt = "<reminder bare>\n\n[Continue the conversation.]"`.

**Consequences.** (a) The system-authority text reaches the model as unframed USER content — neither the real
system channel (the hook) nor the visible `[Note from system: …]` demotion framing; the injections module's own
docstring calls silent conversion "the anti-pattern". (b) The volatile reminder text is recorded into the SDK
session transcript as user content, so the next turn's canon-derived seed diverges → reseed instead of resume
(tail cache-write churn on the sub; the extract-to-hook design exists precisely to avoid entering the
transcript).

**Reachability.** agent-sdk × a `midConversationSystem` model (anthropic-cli × Opus 4.8 —
`domain/connection/catalog/turns.ts:63-66`) × any turn whose pre-nudge history ends on assistant: "continue",
regen-with-empty, and EVERY non-first speaker of a multi-speaker group round (groupNudge). An rpg game chat on
that connection produces the depth-0 system reminder every turn.

**Evidence.** Read of shape.ts, injections.ts, compose/chat.ts (bridge + split + flatten) in full; the shape
test name enumerating the exact [assistant, system, nudge] output; turns.ts capability derivation. Not
live-reproduced (needs an Opus-4.8 continue turn); the code path is deterministic.

### F4 (MEDIUM) — R1 enum over-constraint: scene-NPC removal is UNREPRESENTABLE; cast-actor writes are structurally disabled

`packages/server/src/entry/compose/rpg.ts:171-185` (`resolveExtractionRefs`) +
`packages/contracts/src/rpg/extraction.ts:128-140` (`constrainExtractionSchema`).

**Defect.** `actorRefs` enumerates ONLY the roster (chat participants) + the `player` token — never
`baseState.presentCharacters` keys and never existing `actorState` cast keys (`widgetRefs` DOES come from
baseState, so the state was in hand). The constraint then pins:
- `scene.presentRemove[].enum = actorRefs` — but present-cast entries are minted from `presentUpsert.name`
  (arbitrary NPC names, deliberately UNconstrained). Under an enforcing backend (vLLM xgrammar / OR strict —
  both live per the batch's own comments) the model can NEVER remove a scene NPC it previously upserted:
  "the bartender leaves" is token-level unrepresentable. Scene cast can only grow (or lose ROSTER members).
- `party[].targetRef` / `inventory[].targetRef` enum = roster-only — the documented cast-actor reach
  (`tools.ts:9-10` "Widening update_party.targetRef to reach cast actors…", `tools/apply.ts:74-88` arm (3)
  cast-mint, and D108's "Wallet + inventory FIRST-CLASS" on every actor) is structurally dead in BOTH
  constrained modes: a new NPC can get a presence card but never HP/conditions/items/wallet.

Since the dedicated rounds are now the ONLY model write path (char turn always tool-less), this is not an edge:
it is the whole write surface. The asymmetry (upsert free, remove enum'd; `logExtractionOutcome` treating any
cast mint as a "phantom canary") suggests the R1 fix silently redefined cast actors as illegitimate targets
without a ruling; the in-repo law comments still say the opposite.

**Evidence.** Read of resolveExtractionRefs/constrainExtractionSchema/apply.ts in full; scratch verification
(`reports/stickler/scratch/check-extraction-schema.ts` run output) that the enum lands on
`scene.presentRemove.items.enum` with exactly `["player", <roster names>]`.

## UNCONFIRMED / LOW-PRIORITY SUSPICIONS (not findings)

- Residual stale-read window between the `messageCommitted` bus emit (engine.ts:541) and
  `fireRpgTurnCompleted` (engine.ts:1177): two awaited emits + fire-and-forget setup sit between the
  client-visible commit and the barrier register. A scripted re-send riding the SSE event could in principle
  gather before the register. Microsecond-class vs a network round-trip; not reproduced.
- The barrier tracks only the LATEST flush per chat: after a barrier timeout (or a lock-free generate
  concurrent with a send) two flushes can be in flight and the older one is untracked. Snapshots are
  variant-keyed so no corruption; a reminder could read one-beat-staler state in that corner.
- `THINK_BLOCK_RE` is applied to STRUCTURED output text on both vLLM and OR — a literal
  `<think>…</think>` inside a JSON string value (e.g. journal content quoting it) would be excised.
- Pre-existing (not this batch): the summarize role's resolve-role selector supports pinning
  `max-pro-sub` (isSub arm) and the agent-sdk backend ships a summarize impl, but the firewall's summarize
  row denies max-pro-sub — the "selectable Max-sub summarizer" is unreachable through the executor (D107
  dead-switch class). This batch consciously mirrored the pattern for `structured` (comment acknowledges it).
- The projected extraction schema marks all five array fields REQUIRED (zod v4 output-mode `.default([])`),
  while the prompt says "Emit an empty object when nothing tracked changed" — enforcing backends force empty
  arrays (equivalent outcome); on Anthropic a literal `{}` would burn the runtime's schema-validation retry.
