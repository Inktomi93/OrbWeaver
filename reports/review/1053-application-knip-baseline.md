# 1053: application Knip and the production export baseline

## Outcome

The application stage `deps:knip` (`pnpm exec node tooling/src/verify/cli.ts application-static knip`) now exits 0 on this branch. Its findings were not missing baseline rows: the default Knip view re-judged production-file symbol liveness with no baseline. `knip.ts` now gives that judgment to the production run alone. The production stage `deps:knip-prod` (`pnpm knip:prod`) is unchanged and still exits 1 with 456 real findings, listed below for item 989.

## Two stages, two views

- `tooling/src/verify/lib/registry.ts:296-304`: `deps:knip` runs the default view; its application argv is `application-static knip`.
- `tooling/src/verify/lib/registry.ts:306-314`: `deps:knip-prod` runs `pnpm knip:prod` in both modes, so it is the baselined view.
- `package.json:38`: `knip:prod` passes `--production --strict --preprocessor ./knip-baseline.config.ts`.
- `tooling/src/verify/ops/application-knip.ts:213-236` runs native Knip with `--config knip.application.json` and no `--production` or preprocessor, from `ordinaryConfig({})` (default mode).
- `knip-baseline.config.ts`: the preprocessor returns data unchanged when the run is not production.

The application stage is not `deps:knip-prod`. It never applied the production baseline, by design.

## Which view is authoritative

The production view is authoritative for symbol and file liveness of production files. D318 says Knip reads declared exports "with tests outside the production run, so an export no production package uses is reported". The plan section "Public doors and production usage" says native Knip judges production usage without testkit, tooling or test-only consumers keeping exports alive, and that `knip-production.baseline.json` records shrink-only findings.

## Root cause

Before this change, `knip.ts` `configFor` returned the full `config` unchanged in default mode. Every package workspace then had its production files checked for unused exports, types and files with no baseline. Test-only consumers kept some exports alive. D318 replaced the wildcard doors, so internal barrels stopped being entries, and this default view became red by construction. Nobody saw it, because the stage was a tool error until `1df65d705c`.

Measured on main `49c6957790`, before the fix:

- Application stage: 4 files, 106 exports, 415 types (525 findings), 15 configuration hints, exit 1.
- Every one of the 525 is also a production finding (matched by type, path and symbol, with Knip's truncated paths matched by suffix): 436 are recorded baseline rows and 89 are among the production run's non-baselined findings. None is unique to the default view.
- Plain `pnpm knip` (the implementation argv of the same stage): 6 files, 138 exports, 433 types.

The default view therefore added no information about production files and had no way to go green while D318 debt exists.

## Fix

- `knip-baseline.config.ts`: export `BASELINED_TYPES`, the issue types the production run judges and its baseline admits.
- `knip.ts` `defaultWorkspace`: in default mode, each workspace gets `ignoreIssues` for exactly its `!` project patterns and `BASELINED_TYPES`. The ignore is derived from the production patterns, not a list of findings. Files outside the `!` patterns (for example the `packages/ui` build files and `packages/plugin-toolchain`) keep default symbol checks. Dependency, unlisted, unresolved, binary, duplicate and catalog checks are unchanged. The production branch of `configFor` is unchanged.
- `tests/tooling/knip-workspace-policy.int.test.ts`: a control on the real `packages/ui` row. The default run reports an orphan export in a build file and does not report a test-only export in a shipped file. The production run reports that shipped export. It failed on the old `knip.ts` (the default run reported `shippedTestOnly`) and passes with the fix.

## Was the baseline reconciled against the wrong view

No. The baseline keys are production keys, and `pnpm knip:prod` reports 0 stale keys. The last reconciliation (`9df96aafd5`) ran that view. The 456 non-baselined production findings are new debt that landed while `deps:knip-prod` also could not run. A text check of each symbol against `2a5a7677c7`, the commit that cut the baseline, gives:

- 220 symbols already existed at the cut and lost their production consumer later. For example, `entry/compose/imagery.ts` imported `createExtractQuiet` and `resolveTurnIdentity` from `#domain/chat` then and does not now.
- 166 are new symbols in existing files.
- 70 are in files created after the cut.

The plan forbids widening the baseline ("never add fake consumers or widen the baseline"), so no rows were added. Item 989 adjudicates these findings.
