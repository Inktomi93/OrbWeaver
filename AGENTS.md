# Orbweaver — Codex entry point

Codex does not expand `@path` and does not discover skills by name. A generated Codex agent manifest
(`.codex/agents/*.toml`) can still list specific skill files under `.agents/skills/` (a symlink to
`.claude/skills/`); read the ones your manifest names. Outside a generated manifest, read these files
yourself:

1. Read `CLAUDE.md` in full. It holds the law, the reading router, the verification tiers and the glossary.
2. Before you edit, stage, commit or run the stack, read `.claude/skills/lane/SKILL.md` in full. It holds the lane rules.
3. Before you change a file, read each path rule listed below whose paths match that file.

## Differences from Claude sessions

- Codex has no tool-guard hook. Use the command spellings in the lane skill yourself.
- Git hooks still run. The `commit-msg` hook checks every commit message.
- Codex has no memory. Keep a prior finding in your own working notes.
- After `git worktree add`, run `pnpm worktree:bootstrap` in the new tree.
- Read `.claude/skills/orchestrator/SKILL.md` only when you coordinate other agents.
- Spawn `verifier`, `side-eye` or `stickler` with `fork_turns="none"` and a self-contained brief. Codex forks the full history by default, which ends an independent review.
