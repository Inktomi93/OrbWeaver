# A Map or Set typed by its annotation credits the tuple its key type names

## What

In the unions scan, a literal passed to a Map or Set typed only by its variable's annotation reaches no slot the reader can name without matching the type's identity, so its tuple's members read unbuilt; the cb-slots lane left about six rows lost (REGEX_NOT_APPLIED_CAUSES, REFUSAL_KINDS).

## Why

Each is a lost credit, but crediting by type identity risks crediting a twin tuple of the same texts.

## Done when

A ruling decides whether the annotation's type arguments trace to the tuple's declaration; if so, a planted annotated Map and Set credit their tuple and a twin tuple of the same texts stays uncredited, and otherwise the shape is listed under the unions report's limits.

## Evidence

Filled at landing: what ran and where its output is.
