# Tests that fail under load or on WebKit and pass alone hold on a real signal

## What

One bundle of test cases that fail in a full run, at host load or on WebKit, and pass alone. Each entry keeps its own text. "plugin-topbar-placement overflow case fails inside the full CT run": tests/client/features/plugin/components/plugin-topbar-placement.ct.tsx:131 (placed commands that do not fit overflow before any house control) failed once in a full CT run and passes alone on main and on a lane branch. Done when: The cause is named from the failure trace and fixed at the source, and the case passes repeated full-run-position runs. "entry-editor chip coarse-pointer case fails inside the full CT run": tests/client/features/world-info/surfaces/entry-editor-chip-targets.ct.tsx:91 (a tap 2px into the next chip removes no keyword) failed once in a full CT run and passes alone on main and on a lane branch. Done when: The cause is named from the failure trace and fixed at the source, and the case passes repeated full-run-position runs. "The title reveal's space press case holds under load": In `tests/client/features/chat/components/chat-header-title-reveal.ct.tsx` the case where a host presses Space on a cut title failed once in a merged run, with the reveal not opening, and passed on every repeat of its file. The case likely presses before the control has settled into its cut state. Done when: The case waits on the control's own cut state before it presses, passes on repeat at load, and is still red when Space activation is broken. "The plugin host's stacked-settlement test holds under load": A plugin host test that stacks settlements sizes its work to the box's speed and failed in full-suite runs at load, then passed alone. Its siblings were rewritten to hold a call at the parent for a fixed time and are red against their defects. Done when: The test holds its condition by a fixed hold at the parent or an injected seam, passes in the full plugin host run at load, and is red against its defect. "The room-reads suite keeps its plugin broker under host load": The room-reads integration suite loses its plugin broker under host load, so cases fail on a broker lifecycle error rather than on product behaviour. Done when: The suite passes repeatedly at the load where it lost the broker, and a broker loss fails with a message that names it. "Slow eslint rule tests carry a scaled budget or a faster fixture": eslint-container-ownership and eslint-opaque-variant-spread run cases of three to four seconds against the five-second default timeout, so they fail under load; eslint-ct-responder and eslint-tests-coverage are close behind. Done when: Each of these files runs its cases well under the default timeout through a shared parsed program or a smaller fixture, and passes under the box's normal load. "The census-text captions-at-four-depths case counts every caption under load": In the census-text int suite, the case that plants captions at four depths sometimes counts three affected subjects instead of four when the box is under load; it reproduces with the engine files at HEAD. Done when: The case counts four on every run under load, with the cause named (a timing read, a paint not settled, or a pixel ring racing a frame) and fixed in the walker or the fixture, and a repeat-each run under load passes. "WebKit flake in platform-history-pagination at 1280x900 flat": Find why platform-history-pagination times out in WebKit at 1280x900 flat, and remove the cause without raising the timeout. Done when: The suite passes repeated consecutive WebKit and Chromium runs under whole-suite load at both sizes. "WebKit folder-chooser setFiles timeout in the platform action groups collision case": Find why setFiles times out in WebKit in the platform action groups collision case, and remove the cause. Done when: The case passes 20 consecutive WebKit runs. "The character Import dialog text-scale cases pass on WebKit": In tests/client/features/app-shell/surfaces/platform-text-scale.suite.ct.tsx the character Import dialog cases at 200% and 300% time out in WebKit waiting for the Import button by role; the old source fails the same way, so the failure predates the enlarged-text fixes. Done when: Both Import dialog cases pass in test:ct:webkit, with the cause named: a test locator that misses the button, or a product defect that hides it in WebKit, fixed at its owner. "The context recovery platform suite runs on the WebKit iPhone project": tests/client/features/app-shell/surfaces/platform-context-recovery.suite.ct.tsx fails most of its cases on the webkit-iphone project: its helper clicks a Show details toggle the iPhone layout never draws. It fails the same way on main before the type-law changes. Done when: The suite's helper opens the context surface through the control the phone layout actually draws, and the suite passes on webkit-iphone.

## Why

A test that fails with load gets ignored, and the behaviour it proves goes unwatched.

## Done when

Each listed case waits on a real signal or an injected seam in place of work sized to the box, passes in a full run at load, and is still red against its defect.
