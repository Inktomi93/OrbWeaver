# Complete plugin and protocol output suppliers

## What

Complete plugin result, host callback and browser guest protocol suppliers within the [builder program](0959-one-builder-per-shape-and-one-golden-corpus.md). Preserve native runtime owners and distinguish standalone declaration mirrors.

## Why

Boundary accounting does not qualify protocol suppliers, private material handling or caller-specific output variants.

## Done when

Every owned output and callback has a canonical supplier with meaningful native cases. Private material remains separate and native admission is preserved. Unqualified owned variants are resolved. No parallel protocol or domain harness is introduced.

## Evidence

Selected native lifecycle, source, HTTP, Host returns, callbacks and browser Worker suppliers pass independent security review. Exact log kind, level and payload are asserted. Evidence: `reports/review/1031-plugin-output-delivery.md` and `reports/review/1031-host-1036-identity-independent-security-review.md`. Browser memory-unavailable behavior, unallocated variants and shared adoption remain open. The private allocation failure has no public injection seam; no synthetic unavailable frame or induced OOM establishes that behavior. The injection expansion observation remains unadjudicated, not a confirmed production defect. Further protocol qualification follows the current allocation while independent corpus adoption proceeds.
