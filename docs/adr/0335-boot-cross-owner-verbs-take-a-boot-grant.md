# Cross-owner boot verbs take a boot grant only boot importers can mint

## Context

Boot steps call domain verbs that read or write rows of every owner once at boot. A request route also holds a database handle and reaches the same domain front doors. The per-feature template in Core-0 §4 allows one front door per domain, so a second boot door is not available, and dependency-cruiser cannot tell the named exports of one door apart.

## Decision

A verb that reads or writes rows of every owner at boot takes BootDatabaseHandle, a nominal subtype of DatabaseHandle, so a plain handle fails tsc. bootDatabaseHandle(handle) in packages/db/src/client/wiring-capabilities.ts is the one mint: it registers the same admitted connection under a new frozen identity and records that identity in a grant registry. Each such verb recovers its connection through bootDatabaseForOwner, which refuses any handle the registry does not hold, so a plain handle cast to the boot type throws before a query runs. databaseForOwner rejects a BootDatabaseHandle-typed argument in tsc, because a cast grant is registered as a plain handle and that lookup would accept it. The type check sees only a value typed as the grant: a widening annotation, a plain DatabaseHandle helper or a <T extends DatabaseHandle> parameter reaches databaseForOwner with no cast. For the listed verbs, the forged-grant table is the runtime check that catches that path. The mint reaches callers only through the @orb/db/wiring-boot door. The query-wiring-boot-admission dependency rule admits only the importers BOOT_GRANT_IMPORTERS names in .dependency-cruiser.ts, each with its reason: entry/lifecycle.ts mints once and passes the grant to the boot steps, the seed tools run those steps, and the testkit runs them and hands suites the grant through bootGrantFor. The @orb/db/wiring-owner subpath in packages/db/package.json resolves to packages/db/src/client/wiring-owner/index.ts, which re-exports every owner conversion except the mint. Package resolution therefore closes a static import, a re-export and a dynamic import() of that subpath alike. The query-wiring-capabilities-inside-db dependency rule refuses any import of wiring-capabilities.ts from outside packages/db, whether static or dynamic, by relative path or by the root #db/\* imports alias, so the db doors are the only way in. The boot steps declare db: BootDatabaseHandle, so the grant flows down from the lifecycle and no step mints. A boot-only verb that touches no owner's rows keeps the plain handle; ensureSystemDefaultPreset writes only the ownerless shared row. This extends the D321 pattern: dependency-cruiser owns who may hold a database capability, and the type and the registry carry it. Homes: packages/db/src/client/wiring-capabilities.ts (the type, the mint and the registry), packages/db/src/client/wiring-boot.ts (the door), packages/db/src/client/wiring-owner/index.ts (the owner door without the mint), .dependency-cruiser.ts (the importer rule and the capability-module rule), tests/support/node/boot-grant.ts (the test-side mint), each domain door's note beside its boot verbs (the criterion). Checks: tests/server/entry/boot/cross-owner-boot-verbs.test-d.ts (the verb list, the mint-free owner door and the planted grant verb), tests/server/entry/boot/persistence/forged-boot-grant.int.test.ts (each listed verb refuses a cast grant and moves no row) and tests/db/client/wiring-capabilities.int.test.ts.

## Consequences

A new cross-owner boot verb takes BootDatabaseHandle, recovers through bootDatabaseForOwner, and is added to the type test and the forged-grant table. A request route that needs a cross-owner read cannot get the grant; that read belongs in a boot step or an owner-scoped verb. Every owner-conversion importer of wiring-capabilities.ts, the domains and the request-path owners in transport and observability alike, recovers raw connections but cannot import the mint, so the grant is confined to the importers the rule names.

## Alternatives rejected

A boot.ts door per domain: the per-feature template in Core-0 §4 makes index.ts the only external import, and the #\* imports map resolves only directory front doors (D15). Minting inside each boot step: any entry file could then call the step with a plain handle. A type-only brand: a cast passes every static check, so the registry refuses it at runtime. Restricting named exports by review: no check fails. An ESLint no-restricted-imports ban on the mint name: the rule does not see a dynamic import(), so the exports map closes the subpath instead.
