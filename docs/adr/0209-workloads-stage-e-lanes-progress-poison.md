# Workloads stage E: lanes, durable progress, and visible poison rows

## Context

Split off [ADR 0117](0117-domain-workloads-is-a-generic-execution-substrate-with.md), whose stage-E substrate upgrades and stats.reconcile scope addition pushed it over the 8 KiB ADR cap. Report: the workloads junk-drawer exit review (commit `c8bdf92bf`), report §5 stage E and §6 Q4.

## Decision

**(9) EXECUTION IS A LANE, ADMISSION IS A LOCK — and they never interact.** `workloads.lane` is a real column (CHECK derived from `WORKLOAD_LANES`, D34), stamped at the enqueue door from `contributions[kind].lane` (`start`; `retry` RE-stamps from the kind's CURRENT contribution — a lane is the owning domain's live declaration, not a property of the failed attempt). It is a COLUMN, never a claim-time derive, so lane assignment survives a restart. `nextRunnableWorkload` takes the lane and windows only that lane's queue head; the worker runs ONE poll loop per lane (`laneConcurrency`, a dep defaulted to 1 per lane — owner ruling on report §6 Q5: widening N is a dep, never a migration), sharing ONE boot/periodic reap and ONE wake subscription that resolves every sleeping lane. Each lane's loop stays sequential BY DESIGN; the parallelism is BETWEEN lanes. The §2 head-blocking defect is dead: a 20-minute `import-st` on `sweep` cannot delay a user's `databank-ingest` on `interactive` (regression-pinned with the sweep lane occupied by construction). Every single-active partial-unique index is untouched — locks admit, lanes execute. **(10) PROGRESS IS DURABLE, ON ONE WRITE PATH.** `workloads.progress` (JSON) carries the latest `WorkloadProgress`; `report()` records the snapshot and piggybacks the EXISTING heartbeat UPDATE, throttled to the same 5s lease cadence (`createLeaseWriter` — the heartbeat timer carries the latest snapshot too, so a chatty run costs the same db traffic as a silent one). The 60s in-process replay ring STAYS as the live-tail smoother; the ROW is the reconnect truth — `list` rows render real progress with no subscription open, which is what a tab opened 20 minutes into an import actually reads. The write is status-guarded like every lease write, so progress can never resurrect a terminal row. **(11) THE POISON READ PATH IS VISIBLE, NOT SILENT** (the on-record data-loss footgun, closed): `toView` surfaces a row whose params blob fails its contribution schema as `{…row, params: null, poison: true}` — `list`/`get` show a visibly-broken, cancel/RETRY-able row (retry clones the RAW blob verbatim through `loadRawWorkloadParams`, so the operator's original input survives into a build that fixed the schema). Only an UNKNOWN KIND still drops (deploy skew — it cannot be spelled). The DISPATCH path is correspondingly narrowed to a new `WorkloadRunnableRow` (the healthy case), and `nextRunnableWorkload` fails a poison head row in place: a row can be visible on the read surface and refused by the engine at the same time, by type. **(12) CLIENT:** the pane groups rows by lane (derived from the tuple; the heading is dropped when every row shares a lane — a lone group label is noise), renders the durable `progress` when no live tail is connected, and flags a poison row `Unreadable` with plain copy. **RESIDUALS from the stage-E list, verified already closed at stages A–D:** the dead `subscribeWorkloadEvents` front-door export (gone — the front door exports `subscribeWorkloadWake`, the worker's own seam) and the Constitution.md §6 indexer drift (fixed at D117's mint). **\[SCOPE ADDITION, owner ruling on report §6 Q4]: `stats.reconcile` is a direct tRPC mutation** — the already-proven awaited twin (`reconcileStats`, the same op the import post-settle calls) exposed as the instant "recompute my stats" on the Analytics dashboard. Owner-scoped by CONSTRUCTION: no id input, the rebuild scope IS `principal.userId` (swept EXEMPT with that reason). The `reconcile-stats` KIND stays for the all-owners BULK sweep — that is what the single-active lock + run history are for; `StatsService` gains its first write verb and `StatsContext` gains the injected clock.

## Consequences

The head-blocking defect [ADR 0117](0117-domain-workloads-is-a-generic-execution-substrate-with.md) §2 named is dead: a long-running sweep-lane job cannot delay an interactive-lane job. Progress survives a restart on the row; the 60s replay ring stays the live-tail smoother. A poison row is visible, cancel/retry-able, and narrowed out of the dispatch path by type. `stats.reconcile` is a direct owner-scoped tRPC mutation; the `reconcile-stats` kind stays for the bulk sweep.

## Alternatives rejected

Widen the per-lane worker concurrency instead of adding lanes (rejected by owner ruling on report §6 Q5: widening N is a dep, never a migration).
