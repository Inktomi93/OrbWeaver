# Import identity and additive doors, across split uploads and art attach

## Context

Every single-file import door and the whole-profile import read one parser per entity, and each entity has one content identity. An import that merged a same-named row in place rewrote what the user had edited; a dedup keyed on file bytes imported a re-saved file twice; a dedup keyed on a name merged two different things; and a book whose entries shared a title was refused after the character row existed. The identity also has to hold where a row changes keys or a profile arrives in parts: a JSON card whose PNG later gives it art, an embedded book whose name an owned book already holds, a card name-link that must reach the book its own import landed, and a folder the browser splits into several uploads that each run as a whole import.

## Decision

One parser per entity lives in the serde spine under `packages/server/src/kit/serde/`, beside the native envelope: the world-info, regex and theme serdes detect the raw SillyTavern grammar and map it to the canonical shape, and the whole-profile collector and the single-file doors call the same function. Each entity has one content identity, homed beside its serde. A character is `cardImportHash` over the normalized parsed card, its embedded book and its art (the PNG minus its card chunks); a script's `id`, the wire `spec` and the tag set are not identity. The one exception is a JSON card followed by its PNG with equal text: the art-less row takes the art through `attachImportedArt` and keeps the JSON's identity as a second key in `characters.import_text_hash` (migration `0004_character-import-text-hash`), which `findByImportHash` matches beside `import_hash`, so the JSON still finds the row; a row that already has art makes the PNG a separate character. A world book is its entry set under `loreEntryIdentity` (the typed columns, the engine's metadata keys and the inert SillyTavern activation fields, normalized so a missing field equals its default), whatever its name. A theme is its clamped override and css, a preset its config, a persona its folded name with its free-name count stripped plus description, title, placement and avatar hash. A chat is `chatContentHash` over its parsed header names, create date and ordered messages, with the whole-file hash kept as a second lookup for rows imported before. A regex script is its name plus behavior. Every lookup for a character goes through `findImportedCharacter`.

No import updates or deletes an owned row, except that the JSON-then-PNG attach above writes the art and the second key once. Equal content reuses the row and runs its planes again idempotently; different content under a taken name lands beside it under the next free name, ` 2` from `nextFreeName` for themes, presets and personas and ` (2)` from `nextFreeLabel` for world books, on the standalone door and the embedded-book door (`createBulkImportLorebook`) alike; a character keeps its name and only its handle takes a suffix. A theme backup lands additively too; the backup's palette never replaces a same-named theme. Entry titles are optional and not unique; entries are keyed by id.

A card's world name-link (`extensions.world`, and the profile's `charLore` extra books) binds the row its own import's worlds wave landed or reused for that name, whatever name the row carries: `importCollectedWorlds` returns the landed map and `AttachOwnedBooksByName` takes it as `landed`, re-proving each id owned. A name the import did not carry binds the newest owned book of exactly that name. A split folder upload sends `settings.json`, the persona avatars (`User Avatars/`) and the world books (`worlds/`) in every upload (`planTreeImport`), so each upload resolves personas and name-links as the whole folder would.

## Consequences

An export re-imports as the character, book, theme, preset or persona it came from, and a re-saved transcript is one chat. A JSON card, its PNG and the JSON again are one character. A first import that stopped after the character row was written finishes on the next import. A book edited only in SillyTavern's kept activation fields is a different book, so the edit is never lost. A re-import with changed lore links its cards to the numbered twin it landed, never the stale book holding the bare name. A folder split into several uploads mints each persona once, with its avatar, and its transcripts attribute to it; each upload pays the bytes of the avatars and world books again. A preset whose stored blob the build cannot read is not healed by re-importing its backup; the file lands beside it and the editor marks the unreadable row. Two different personas under one name show as the name and its numbered twin. The `upsertEntries` stream, keyed by title, lands on the newest row when a title repeats. `tests/server/entry/import/import-identity.suite.int.test.ts` holds the four cross-door cases.

## Alternatives rejected

A parallel SillyTavern parser layer beside the serde spine: a second home for each shape. Keep the merge-in-place for backups and go additive only for profile imports: the preflight promise covers both doors, and two rules under one button are a lie. Dedup by file bytes: a re-saved file imports twice and an export never matches its import. Dedup by name: two different things merge. Disambiguate repeated entry titles at import: titles are SillyTavern's optional comment and the engine keys entries by id, so the uniqueness check protected nothing a user could see. Match an art-less persona against owned rows by everything but art: two personas that differ only in art both match, and transcripts attribute to whichever wins. Leave `import_hash` on the JSON identity after the art attach: the PNG would then miss its own row and mint an alt-art duplicate.
