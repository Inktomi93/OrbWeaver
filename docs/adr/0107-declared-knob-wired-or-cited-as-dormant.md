# A declared knob is wired or cited as dormant

## Context

Not recorded in the ledger row.

## Decision

**A declared knob is WIRED or CITED-DORMANT; DOORWAY vs DEFERRED is the dormant-vs-dead distinction.** A settings field/section/leaf, an `AppSettings` admin-editor key, a `DEFAULT_FORMAT_STRINGS` format string, or a `chatMetadataSchema` field that validates + stores but is never WRITTEN or never READ is a **dead switch** — an edit silently governs nothing (the `rateLimits` dead-ended-pair, the permanently-OFF `memory.enabled`, the read-by-nobody `dupThreshold`). The `knob-wire-coverage` gate makes it structural: every declared knob has its missing half wired, OR carries a cited entry in ONE of two module-const registries, each self-cleaning in BOTH directions (the D50 bus-coverage ratchet discipline — a member that GAINS its wire REDs its stale entry; a member that LOSES it REDs missing). The two registries encode the owner's dormant-vs-dead ruling as first-class state: **DOORWAY** = a SANCTIONED, indefinitely-dormant rebuild seam (a declared doorway a purged/future domain will graft onto — never re-litigated, only stale-checked); **DEFERRED** = TRACKED DEBT with a remediation cite (a knob that SHOULD be wired and isn't yet). The canonical "declared doorway later wired" success story the DOORWAY state exists to protect is `workloads.dependsOn`/`scheduledAt` (declared unwired, since fully wired: client run-dialog + tRPC + the scheduler DAG gate) — DOORWAY is what lets that pattern ship without an orphan-export gate fighting "unwired ≠ worthless" (Core-0 §1). **The databank settings machinery is WIRED (Phase B ④ — was a sanctioned dormant doorway by owner ruling, commit `09cd25525`):** `UserSettings.databank` (`{chunk, retrieval:{k,minScore,rerank}, slotTokenBudget}`, schema v5) now exists with a client write path (a settings-section contribution at the chat-behavior anchor); the compose `getDatabankSettings(ownerId)` reads the user's real section via `loadUserSettings` (the 0-param schema-default stub is gone — it fed ingest chunk params too); and the retrieval params ride ForeignInputs → `gatherRetrieval` → `search.documents` (`k`/`minScore`/`rerank` consumed field-for-field, defaults byte-identical to pre-wire — reuse-seam-check-both-ends verified). A composed-real int test (`tests/server/entry/compose/databank.int.test.ts`) pins a settings write → the composed read; the `assemble-gather`/`gather-retrieval` int tests pin the settings→gather-op→searchDocuments threading. SCOPE BOUNDARY: the final embed/cosine hop needs vLLM (down for owner GPU work), so the retrieval-param-change OBSERVABLE end-to-end is engine-gated; the settings→read and read→search halves are both pinned. **The `agent-runner` `DEFAULT_AGENT_MAX_OUTPUT_TOKENS = 4096` twin dies with the buddy rebuild** (a diverged shadow of `@orb/contracts/preset`'s `DEFAULT_MAX_OUTPUT_TOKENS = 2048`, dormant since buddy's purge — the rebuilt caller feeds preset `maxOutputTokens`); WITH that rebuild it becomes a `schema-banned-shapes` row (import the contracts const). **`rateLimits.general` was DELETED, `rateLimits.login` ADDED (Phase B ③):** `general` was a dead-ended field — never consumed (no enforcement point distinct from the `authed`-capped `general`-SCOPE bucket), its name poisoned; the field + its `RATE_LIMIT_GENERAL` env floor + the resolver case are gone (deleting it loosened nothing, it drove no bucket), and re-add is gate-safe. `login` is the per-IP login-attempt cap (env floor `RATE_LIMIT_LOGIN=10` ⊕ admin override) threaded live into the existing auth-route throttle. **`workloads` WIRED + `personaWizardSeen` DELETED (Phase B ⑤/⑥):** the `workloads` section (dupThreshold/computeThemesK/maxPairs/hubFraction) gained its client write path (a workloads-tuning contribution at the `workloads` anchor; the cooccurrence maxPairs/hubFraction runner-env op was widened to thread them) — `B:workloads` pruned; `personaWizardSeen` was a dead onboarding field READ + WRITTEN by nothing (the first-run persona gate triggers on zero owned personas, never a "seen" flag) — deleted (the `rateLimits.general` precedent), `C:personaWizardSeen` pruned with it. **`toolRecurseLimit` gained its host control (Phase B ⑦):** the room-settings Tool-use control (chat context panel Settings tab, host-only) writes the existing `chat.setToolRecurseLimit` verb; `ChatDetail.toolRecurseLimit` was exposed for the read (both-ends). **Chat prefs + preset + library WIRED (Phase B ⑧⑨⑪):** ⑧ the temporary-chat reap TTL de-hardcoded from `TEMPORARY_CHAT_REAP_TTL_MS` to `chat.tempChatTtlHours` (the reaper is per-user — it scopes to the caller's own hosted chats — so a per-user knob is the honest tier; read via a new `resolveTempChatTtlHours` ChatContext op, compose-wired off `loadUserSettings`), and the auto-retry bounds gained their knobs: `chat.autoSwipe.maxRetries` (`runAutoSwipe` reads `cfg.maxRetries`, replacing `AUTO_SWIPE_MAX`) and `chat.autoContinueRounds` (`runAutoContinue` takes a `rounds` arg from `behavior.autoContinueRounds`, replacing `AUTO_CONTINUE_MAX`) — both threaded through `ChatBehaviorInputs`/ForeignInputs;
