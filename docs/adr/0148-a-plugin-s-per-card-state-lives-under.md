# a plugin's per-card state lives under the RESERVED card namespace `data.extensions.plugin_<slug>`; it is portable, key-namespaced, and INERT — a plugin can never read or overwrite another plugin's `plugin_<otherslug>` field, nor promote its own value into a typed card column

## Context

Not recorded in the ledger row.

## Decision

Owner-approved 2026-08-28 (#679 U8, the ST `writeExtensionField`/V2-card-`extensions`-object parity arm). ST extensions persist arbitrary per-card state under the card's `data.extensions` object; orbweaver already carries that object losslessly (the character card serde's `residualExtensions`, `kit/serde/card/index.ts`), so this ruling RESERVES the `plugin_<slug>` key prefix inside it as the one home for a plugin's per-card state and states the security properties that home guarantees. **Four clauses.** (a) **PORTABILITY IS FREE, BY THE RESIDUAL-EXTENSIONS MECHANISM.** `cardFromJson` keeps every `data.extensions.*` key MINUS the fields with a typed column (`depth_prompt`/`regex_scripts`/`fav`) in the `characters.extensions` JSON column, and `buildCardV3` re-emits them verbatim — so a `plugin_<slug>` blob round-trips import → store → export → re-import unchanged, to SillyTavern and back. No new column, no new serde path: a plugin key is a residual vendor extra, and the residual passthrough is what makes per-card plugin state portable. (b) **NAMESPACING + WRITE ISOLATION IS HOST-STAMPED, the D146(c) precedent one plane over.** The write path (`host.character.setCardData`/`getCardData` — capability + host-fn, the reserved consumer this ruling governs) derives the key as `plugin_<slug>` from the RE-VALIDATED manifest slug at the membrane, NEVER from guest input, and merges/reads exactly that one key of an INSTALLER-OWNED character's `extensions` object (owner-scoped by the persistence `WHERE owner_id` predicate — a foreign character is the leak-free `PluginNotFoundError`). So plugins' fields coexist by key, and a plugin can reach only its own `plugin_<slug>`: it can never name, read, or overwrite another plugin's `plugin_<otherslug>` field, because it can never spell another slug. (c) **INERTNESS: a plugin value CANNOT become a card directive.** Only TOP-LEVEL `data.extensions.*` keys promote to typed columns; a `depth_prompt`/`regex_scripts`/`fav` nested INSIDE a `plugin_<slug>` value stays inert data under that key and never reaches the card's own `depthPrompt`/`regexScripts`/`starred`. An untrusted imported card therefore cannot inject a system directive or a regex script through a plugin namespace. (d) **THE WRITE IS METADATA, NOT CONTENT — no re-embed, no contentHash bump.** Per-card plugin state is not card prose; writing it does NOT recompute `contentHash` or emit `character.updated{contentChanged}`, so a plugin persisting state never re-indexes the character (the opposite of the `create`/`update` verbs). ENFORCEMENT, tiered honestly: clauses (a)+(c) are behavioural at the serde tier — the round-trip + namespacing + inertness (a hostile `plugin_evil` value mimicking the promoted fields, refused promotion) are pinned in `tests/server/kit/serde/card/index.test.ts`; clause (b)'s slug-stamp + owner-scope are the membrane's host-fn wiring (the `pubsub`/`character.ingest` host-stamp precedent) and its plugin-host suites; clause (b)'s "no cross-plugin read/overwrite" has no gate that distinguishes a host-derived key from a guest-supplied one, so it is REVIEW-tier — stated at the write host-fn and its bridge, the thing a reader must not weaken to a guest-supplied key. STATUS: **all four clauses LIVE and proven.** The namespace + portability (a, c) landed with the serde; the write host-fn (b, d) landed as the `character.card_state` capability + `host.character.setCardData`/`getCardData` (membrane → `PluginBridge`/`PluginHostOps.character` → the character domain's owner-scoped `writePluginCardData`/`readPluginCardData` `json_set`/`json_type` merge on `characters.extensions`, wired at `entry/compose/automation-plugin.ts`; the key is `pluginCardStateKey(slug)` = `plugin_<slug>`, stamped host-side at the bridge). Slug-isolation (A's atomic one-key merge leaves B's field byte-identical), owner-scope (a foreign character is the leak-free `PluginNotFoundError`), and no-re-embed (the merge never touches `contentHash`) are pinned red-first in `tests/server/domain/character/persistence/plugin-card-data.int.test.ts`; the membrane capability-gate/forward in `tests/server/infra/plugin-host/membrane.test.ts`; the host-stamped-slug wall in `tests/server/domain/plugin/substrate/bridge.test.ts`.
