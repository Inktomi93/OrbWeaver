# The Tracker is the ONE tracked-field concept (SUPERSEDES the pool/cast-field/widget trichotomy)

## Context

Not recorded in the ledger row.

## Decision

`RpgTrackerDef` (`packages/contracts/src/rpg/tracker.ts`) — `key/label/shape(meter|text|list)/write(delta|set)/subject(actor|game)/appliesTo/max/hint/color/icon/sort/pinned/locked` — homed ONCE in `config.trackers[]`. \*\*(1) \[AMENDED, owner ruling — stage 2 `98ee6da2`] The value plane is `RpgTrackerValue = {value, max?, items}`: `def.max` is the DEFAULT ceiling; `value.max` is a PER-CARRIER OVERRIDE (absent = the def's; two characters CAN carry different Vitality ceilings — the d20 max-HP reality). Effective ceiling = `trackerCeiling(def, value)`, ONE resolver beside `carriesTracker` — every consumer (panel bars, band orbs, reminder gloss, delta lines) reads it, nobody re-derives. Anti-drift: `resolveTrackerMaxOverride` writes the override only when it differs from the default and CLEARS it on write-equal — the always-duplicated drift class stays dead without banning the data. Max stays HOST-AUTHORED (no model write surface; a model delta preserves an override — pinned). The Status-row max edit rides the actor's value plane (`editSnapshot`), the Game-tab editor edits the def's "default max". \[The original stage-1 no-max-at-all shape was an executor deviation from spec §5.2 that shipped for ~half a day; superseded here.] Value homes: `actorState[].trackerValues` (actor subject, INCLUDING `cast:` NPCs — `presentCharacters.customFields` is GONE) and `snapshotState.trackerValues` (game subject). **(2) Carrier resolution is one-homed:** `carriesTracker` (revoke > grant > class) in `tracker.ts`; `trackersForCarrier`/`resolveTrackerCarriers` derive from it; resolved ONCE in `buildTrackerView` and handed down — no consumer re-derives. `appliesTo`'s explicit branch holds actor-ref KEY STRINGS, not embedded `RpgActorRef`s (`tracker.ts` ↔ `actor.ts` would cycle); the carrier CLASS is supplied by the caller. Per-actor overrides ride `sheet.trackerGrants[]`/`trackerRevokes[]`; the ONE asymmetry: `cast:` NPCs have no sheet row, so per-NPC targeting uses the explicit list. **(3) DB is a NO-LEGACY clean break** (rebuild-era posture): `rpg_hud_widgets` DROPPED, `widget_values` → `tracker_values`, one regenerated baseline — no lift machinery. **(4) R6 extraction schema is PER-CALL GROUPED:** actors bucket by identical writable-tracker signature — one bucket ⇒ flat schema (the common game pays nothing), several ⇒ a `oneOf` branch per bucket pinned by `targetRef`; `locked` trackers never enter the schema; a branch with no keys is REMOVED (never an empty-enum husk); `set_tracker` disappears entirely when no game-subject tracker exists. **(5) R2 tool descriptions are game-rendered from ONE template home** (`buildRpgToolDescriptions(ctx)`, `contracts/rpg/extraction-prompt.ts`); `RPG_BASELINE_TOOL_DESCRIPTIONS` is the zero-config render the registry defs read — registry and wire CANNOT disagree. **(4b) THE READ SURFACE SHOWS EVERY TRACKER, ALWAYS** (the twin of ruling (4), and the live-turn bug it was born from — a pinned `Corruption 0/100` on every Status card that the whole reminder mentioned NOWHERE): the reminder teaches the tracker VOCABULARY ONCE per turn (`Trackers: <label> (<hint>)`, `trackerVocabulary` — the `attributeGloss` twin) and every reading below carries only `label value/max` (`trackerReading`); a CARRIED tracker with no reading yet lists its bare LABEL on its carrier's line (carriage is the datum when there is no value); a carrier with NO volatile row still lists what it carries (trackers render off the CARRIER set, never off a stored key set); a ZERO reading is state and renders. `locked` filters the WRITE surface ONLY (`buildTrackerWriteGroups`/`gameTrackerWriteKeys`/the extraction schema) — a lock in `buildTrackerView` or the reminder segs is a DEFECT (the reminder is the model's knowledge, the tools are its permissions). The reading-bound `trackerGloss` survives only for surfaces with no vocabulary line above them (the delta's standalone `{{rpgDelta}}`/`rpg.delta.text` consumers). **(6) Vocabulary:** TRACKER in all code/UI (`set_widget_value`→`set_tracker`, `poolDeltas`→`trackerDeltas`/`trackerSets`, `poolOrbs`→`trackerOrbs`, `RpgWidgetId` brand deleted); `cast:` actor refs + `view.cast` are ROSTER-people semantics and stay. STAGE 2 OPEN: Status-absorbs-Sheet takeover view, GM Tracker editor polish (the Status max-edit now honestly writes `updateConfig` — a game-wide edit from a per-actor row, flagged for side-eye).
