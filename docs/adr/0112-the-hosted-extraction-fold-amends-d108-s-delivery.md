# The hosted extraction fold (AMENDS D108's delivery fork and D109-1's tool-less rule; spec: `docs/design/rpg-extraction-one-call-spike.md`)

## Context

Not recorded in the ledger row.

## Decision

`config.extractionMode ∈ {reliable, cheap, **folded**}` — a THIRD union member, deliberately NOT a capability-derived refinement of `cheap`: no capability flag distinguishes hosted-strong from the local 8B (both advertise tools — vLLM runs hermes), R3 scopes the fold to hosted for ACCURACY not capability, a `credential.source` branch in `domain/**` would breach the Tier-3b seal, and D108's honest-cases discipline wants the host's deliberate lever, never a secret re-route. **(1) D109-1 is now mode-scoped:** the gather's REGISTRY tools stay `[]` in every mode; `folded` mounts the 7 state tools on the character turn as TERMINAL tools, `tool_choice:"auto"` — NEVER `"required"` (0/6 narratives, §3). **(2) NEW LAW — TERMINAL TOOLS are a chat-engine primitive** distinct from registry tools: attached to the wire, never resolved to a `ChatToolSet` (so `pivotCalls` returns null and the recurse loop breaks at depth 0 — the one-call co-emission mechanism), never executed, never minted as `ToolCallRecord`s, returned raw to the contributing feature on a channel whose `null` (no terminal capability on this wire) vs `[]` (capable, none emitted) distinction is TOTAL and essential. Thread: gather `terminalTools` → TurnPrep → `runTurnPipeline` → `attachTerminalTools` → `TurnPipelineResult.terminalToolCalls` → `onTurnCompleted` → `flushTurn` → the SAME `toolCallsToExtraction`/`extractionToStateDelta` fold the round uses. Only `executeTurn` threads them (never `generateTextUnpersisted`). **(2b) The MOUNT half is PRE-COMMIT** (inside turn assembly): any pre-commit gather contribution that does I/O MUST be caught errors-as-data — a failed fold-mount logs `rpg.extraction.fold_build_failed` (loud, via the injected hook — `domain/rpg` stays logger-free), proceeds tool-less, and the flush's `null` channel runs the fallback round: a failed mount costs a CALL, never a BEAT (hardening `5fb7816a`, verifier-driven — with the null-economics totality fix \[`economics===null` → channel `null`, never a fake quiet beat] and the flush fold trimmed to ONE db read, `reachableActorRefs` one-homed under `ghostTargetRefs`). **(3) \[AMENDED, EXT-4 `9b140933`] Degrade is errors-as-data, total, narrative-inviolate, and PER-ENTRY on every vehicle:** the reliable/structured case no longer whole-object-parses — `salvageExtraction` (contracts/rpg/extraction.ts) parses per plane/per entry and itemizes `dropped: [{plane, index, issues}]` INTO the `rpg.extraction.unparseable` event (the log cannot disagree with what applied, by construction); the tool vehicles log through the one `malformedToolCalls` home (truth-repaired with D121 — the name `logMalformedCalls` above was a phantom; `contracts/rpg/extraction.ts:700` is the real one-homed predicate, as this entry's original clause below already names correctly). NEW INVARIANT: a malformed entry costs THAT ENTRY, never the turn's other planes — and all three delivery vehicles leave IDENTICAL surviving state for the same malformed payload (pinned by the EXT-4a three-vehicle test). Observability set gains `rpg.extraction.healed` (the journal type heal, `healedJournalTypes`). Journal hardening: `journal[].type` optional + healed-to-`note` in zod, RE-REQUIRED in the projected grammar via `requireField` (enforcing backends prevent, non-enforcing heal — the documented LOOSE-ZOD + STRICT-PROJECTION pattern, extending D109 (6) beyond `title`). Quest objectives merge BY TEXT (matched lines keep id+completed) + `completeObjectives` marks done without restating — the remint-wipes-completed class is dead. Original clause: Degrade is errors-as-data, total, narrative-inviolate: malformed arg → dropped + `rpg.extraction.unparseable` (via the one-homed `malformedToolCalls()` predicate mirroring the fold's silent drops — the `ghostTargetRefs` precedent, a log can never disagree with what applied) · ghost actor → R5 guard · ZERO calls → a legitimate quiet beat, `rpg.extraction.folded.quiet` info, distinct from failure · `terminalToolCalls === null` (agent-sdk wire) → falls back to the cheap post-commit round with `rpg.extraction.path` WARN + `fallbackReason` — **a delivery fork that resolves silently is BANNED** (`onStateRoundPath` observability). **(4) Freshness corrected:** `LIVE_AT_COMMIT = {reliable:false, cheap:false, folded:true}` — `cheap` was lying "Live" since D109 moved it post-commit; only the fold lands state WITH the turn. KNOWN GAP: the fallback case still shows "Live" while actually rounding — the honest fix (effective-delivery on `RpgGameView`) rides the ResolvedWarning client surface item (EFF-3). **(5) Member visibility:** terminal tool_calls have exactly ONE consumer (`fireRpgTurnCompleted`); they never enter `toolRecords`/`MessageView.toolCalls`/stream deltas — pinned. **(6) Coupled sites for a new `extractionMode` member (~6, all Record-dispatched → tsc-total):** contracts tuple · `readonly-axis` `HAS_WRITE_PATH` · flush `POST_COMMIT_ROUND` + `POST_COMMIT_PATH` · client `EXTRACTION_CONSEQUENCE` + `LIVE_AT_COMMIT`. `isReconcileBeat` re-homed to `chat-ops/reconcile-cadence.ts` (gather + flush must not disagree). Fold economics (spike, Sonnet 5/OR): ~43% cheaper, ~34% faster, 6/6 co-emission.

Split off for the 8 KiB ADR cap: `folded` as the born default [ADR 0205](0205-folded-extraction-is-born-default.md), the agent-sdk terminal-tool channel [ADR 0206](0206-agent-sdk-terminal-tool-channel.md), the local-engine fold guard [ADR 0207](0207-local-engine-fold-guard.md), and the deletion of `reliable` [ADR 0208](0208-reliable-extraction-mode-deleted.md).
