# Legacy tests run and typecheck without semantic extraction

## Context

Legacy tests provide regression coverage during replacement. Executing that coverage does not require semantic inventory extraction or typed source analysis.

## Decision

Keep legacy tests in the repository and CI regression execution. Preserve their native typecheck programs and compiler options.

Exclude canonical legacy worlds from semantic fact extraction. Exclude legacy files from typed gate and provider populations and type-aware lint. Preserve cheap legacy admission and boundary checks.

Derive eligibility from the canonical world and test-kind inventory. Preserve complete native options, roots and resolved closure for every eligible selected program.

Make analysis scope part of demand, generation identity and completeness. Do not reuse all-world qualification as evidence for a changed scope.

This exclusion grants no production boundary permission. Production cannot move into legacy to escape checks. Rebuilt tests receive full maintained analysis.

## Consequences

The regression net remains executable and typechecked while deep analysis serves maintained code. Existing extraction evidence retains its original scope.

## Alternatives rejected

Deleting regression coverage before replacement loses meaningful cases. Extracting legacy semantic worlds merely to retain CI coverage repeats work without establishing maintained-code correctness.
