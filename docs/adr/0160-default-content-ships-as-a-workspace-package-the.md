# DEFAULT CONTENT SHIPS AS A WORKSPACE PACKAGE THE SERVER DECLARES, resolved by node resolution; the first one is `@orb/showcase-plugins`

## Context

Not recorded in the ledger row.

## Decision

Owner-ruled 2026-09-02 (#1238, verbatim: *"if dockerfile which we don't even use yet is moving default assets around that's a nah from me dog — that's crunchy and fragile"*, plus *"our seeded teaching plugins are not in an easy to reach place and they rot — make a new package for them, like we did with tooling"*); landed 2026-09-05 (#1692). The nine showcase plugin bundles, the authoring guide and the published SDK mirror `host-v1.d.ts` live at `packages/showcase-plugins/bundles/`; the packer that turns one into installable bytes is that package's `src/index.ts` (`SHOWCASE_PLUGIN_SLUGS`, `packShowcaseBundle`, `readShowcaseManifest` — the versions are read from the manifests, never re-spelled). **What the ruling refuses** is the shape it replaced: the bundles sat inside the former entry/boot seed-assets/plugins directory (retired 2026-09-05) *because* that is the tree the container image copies, so default content was load-bearing on an image build step — invisible to the toolchain, silently divergent per environment. A workspace dependency resolves identically in dev, on bare metal and in any future container, and a plugin author reaches `packages/showcase-plugins/` instead of five directories into a server tier. **Position follows REACHABILITY, not the "like tooling" mechanism:** `@orb/tooling` sits ABOVE the cake because nothing at runtime consumes it; this package is consumed at runtime by the server's per-user seeder, so it sits BELOW `server`, beside `contracts`/`db`, and may reach only `@orb/kit` + `@orb/contracts` (the bundle-entry vocabulary + `pluginManifestSchema` — the same authority the install funnel judges by). **The seam is the INJECTED op, not an import into the domain:** `entry/compose/services.ts` wires `packBundle: packShowcaseBundle` into the seeder, which knows the slug tuple and nothing about where bytes come from; the bundles still land through the unchanged `install` + `setGrant` verbs, so the consent posture (\[\[D147]]) is untouched. **What this row does NOT rule:** the sibling default-content families (`seed-assets/avatars`, `seed-assets/demo-chats`) are the SAME class and still ride the server-src copy — named here so a reader does not read their absence as an exemption. And the guest `.js` sources remain compiled by NO type program (`allowJs: false` repo-wide); the package's `checkJs`-against-`host-v1.d.ts` program is the rot half of #1238 §2 and is its own row. Enforcers, in ladder order: the pnpm workspace dependency is RESOLVE-TIME physics (an undeclared import does not resolve); the `showcase-plugins-cake` + `browser-no-showcase-plugins` dep-cruiser rules name the direction at lint time; and the byte-identity pin `tests/showcase-plugins/index.test.ts` holds the packed sha256 of all nine bundles, so a content edit reds exactly one row where a reviewer can see the installed bytes changed. \*\*AMENDED 2026-09-18 (owner ask, "the manual copying of files and backgrounds and characters needs to go to proper seed stuff"): the second family landed — `@orb/default-content` (`packages/default-content/`) owns the per-user seed CONTENT that is bytes rather than code: `avatars/<handle>.png` (the default-character pack + the persona art) and `demo-chats/<slug>.jsonl` (verbatim export-verb output), read by that package's `src/index.ts` (`readSeedAvatar`, `readSeedDemoChat`). the former boot seed-assets directory under `entry/boot/` is DELETED; `entry/compose/{assets-character,services}.ts` close over the package's readers and inject them, so the seeders stay fs-unaware and no `domain/**` module imports the package. Position: BELOW `server` beside `contracts`/`db`, reaching `@orb/kit` alone. What the amendment does NOT move: the character card DEFINITIONS (`domain/character/seeder/cards.ts`), `seed-themes.ts` and `seed-default-preset.ts` — TypeScript literals that ride the ordinary source copy and carry domain semantics; the ruling refuses IMAGE-COPY dependence for opaque bytes, not code. `readSeedGalleryPiece` is deleted with the move (its placeholder art was dropped at `bb6d50646`; the reader had returned null since). The container image discovers every `@orb/*` package from the server's production graph (`docker/assemble-runtime.sh`), so a content package needs no Dockerfile line — the exact fragility this row refuses. Enforcers: the workspace dependency (resolve-time); the `@default-content` population root (tsc-forced `AUTHORED_MEMBERSHIP` classification; without it the reader's waivers bind to nothing); the `default-content-cake` + `browser-no-default-content` dep-cruiser pair with fixtures; `tests/default-content/index.test.ts` (sha256 of all 17 shipped files, two-way against the on-disk inventory). **Amendment #2 (2026-09-18, `312474261`): the third family landed** — the ten scene plates ship as `packages/default-content/backgrounds/*.jpg` (`SEED_BACKGROUND_PLATES` + `readSeedBackground`), lifted per user through `assets.store({kind:"background"})` by `domain/settings/seeder/backgrounds.ts` (latched by `onboarding.defaultBackgroundsSeeded`, deduplicated by content hash), so a plate is an ordinary owned `backgroundLibrary` entry. `kind:"seeded"` and the static catalog (the contracts theme seeded-backgrounds module and the client public backgrounds folder) are DELETED; `BACKGROUND_IMAGE_KINDS` is `none|external|asset`; three domain-owned raw-JSON rewrites migrate stored `seeded` picks (settings, character, chat) on every seeder pass. The four landscape placeholders were deleted, not migrated (a pick of one becomes `none`).
