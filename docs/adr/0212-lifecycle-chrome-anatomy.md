# The lifecycle chrome anatomy: band, kebab, and zero chrome in editors

## Context

Split off [ADR 0121](0121-the-close-out-ruling-for-the-preset-and.md), the close-out ruling for the preset and actor-state programs, whose seven independent clauses (A–G) pushed it over the 8 KiB ADR cap. This clause stands alone, as the original states.

## Decision

**(D) The lifecycle CHROME ANATOMY is law: band = Import · kebab = Export · zero lifecycle chrome in editors and rooms.** Import is the LIST panel's band affordance; export is the list row's kebab; an editor surface or a chat room carries NEITHER (CT-pinned absence is the shape of the proof). Per-family placement: character/chat/preset LANDED · persona re-homes onto the anatomy · world-info gets band+kebab when its single-book doors land · user-settings/gallery/assets live in the backup pane, the ruled home for account-wide bundles. A single-entity door is a THIN CASE over the bundle descriptor it shares — never a second serialization path.

## Consequences

Import is the list panel's band affordance, export is the list row's kebab, and neither appears in an editor surface or a chat room — CT-pinned absence is the shape of the proof. A single-entity door is a thin case over the shared bundle descriptor, never a second serialization path.

## Alternatives rejected

Give each family its own import/export placement (rejected: a per-family chrome anatomy is the drift the anatomy law exists to stop).
