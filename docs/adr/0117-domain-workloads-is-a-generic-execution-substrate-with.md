# `domain/workloads` is a generic execution SUBSTRATE with ZERO domain knowledge; every job is a `WorkloadContribution` raised by its OWNING domain. SUPERSEDES \[\[D4]] (~~`WorkloadRunnerEnv` builder = `entry/compose/runner-env.ts`~~) — that file and that type are DELETED

## Context

Not recorded in the ledger row.

## Decision

The rot named precisely: ~~`domain/workloads/contract/runner-env.ts`~~ called itself "the one true cross-feature composition seam", i.e. a LICENSED backdoor — any agent needing another domain's capability inside async work could add an op to the hub + a runner instead of building a proper injected-op seam at the owning domain's door. That is how 32 runners accreted before the purge, why import logic lived outside the portability core, why `entry/compose` ran `db.select` over `characters`, and why one background job cost ten coupled edits across five tiers with ZERO of them in the owner's tree. **(1) THE SEAM:** `WorkloadContribution<K>` (`domain/workloads/contract/contribution.ts`) = `{kind, params (the kind's zod schema), lane, resume, run(ctx, params, report, signal)}`. It homes in the workloads domain and NOT in `contracts` — its `run` takes an `AbortSignal` and `@orb/contracts` is deliberately isomorphic with no dom/node lib (the same constraint that keeps `PortableEntity.exportAll` signal-free) — and owning domains reach it TYPE-ONLY through the front door, the sanctioned cross-feature shape import. Everything DOM-free lives in `@orb/contracts/workloads` (now a directory-module: `axes` · `params` · `result` · `execution`): the kind/mode/status/source tuples, the new `WORKLOAD_LANES`/`WORKLOAD_RESUME_POLICIES` axes, `WorkloadProgress`, and the per-dispatch `WorkloadRunContext` — identity + clock ONLY (`roleClients` had a measured consumer count of ZERO and left the engine; `loadUserSettings` became a discovery-factory dep). **(2) THE 10th ROOT SLOT:** a domain's background work homes at `domain/<x>/workload-contributions.ts` — ratified cross-domain, exactly like `guard.ts`, in BOTH the `feature-structure` gate's `ALWAYS_ALLOWED_ROOT_FILES` and the dep-cruiser `domain-substrate-mediates-subsystems` `pathNot` (it is a composition surface, like service/index/context). Its DI bundle homes in that domain's `contract/`. **(3) THE COMPLETENESS PIN:** `entry/compose/workload-contributions.ts` spreads every owner's factory through `keyByKind`, which asserts exhaustive + duplicate-free registration; `WorkloadContributions = {readonly [K in WorkloadKind]: WorkloadContribution<K>}` makes a missing kind a tsc error AT COMPOSE. Re-accretion is structurally impossible because there is no hub left to accrete INTO. **(4) PARAMS/RESULT FOLLOW THEIR OWNER** (the `IngestRunResult` exception generalized): `EmbedPassResult` → `@orb/contracts/embeddings` · the two analytics params schemas + `AnalyticsResult` → `/discovery` · `ReconcileStatsWorkloadResult` → `/stats` · `CatalogRefreshResult` → `/connection` · `FsckReport` → `/assets` · `BackfillPassResult` + `MemoryBackfillResult` → `/chat` (NOT `/memory` — that direction makes `#memory` and `#workloads` import each other; dep-cruiser caught it). `indexWorkloadParams` deliberately STAYS in workloads: its one field IS the queue's single-active lock sub-partition. Genuinely generic shapes (`MaintenanceResult`, `maintenanceWorkloadParams`, `emptyWorkloadParams`, `DeferredResult`) stay central. **(5) THE 18-CASE `startWorkloadInput` UNION IS DELETED.** The wire validates an ENVELOPE (`startWorkloadEnvelope`: a known kind + a params object); the AUTHORITATIVE per-kind validator is `contributions[kind].params.parse(...)` at the `start` door (`substrate/params.parseWorkloadInput`, which maps a parse failure to a BAD_REQUEST domain error) and on the row READ path (`toView`). The envelope→per-kind widening is contained in ONE named function, `asStartWorkloadInput`. Consequence: the verbs + persistence take the registry, so `WorkloadServiceContext` carries `getContributions()` as a LATE-BOUND thunk (compose order is circular by nature — the registry spans every owner, chat is built last, and import needs `workloads.start`; the `getPortabilityRegistry` precedent). **(6) DEFECTS FIXED BY THE MOVE:** the `assets-backfill` gather (`db.select` + per-row CAS probes) left the ENTRY tier for `domain/assets` — `entry/compose` now contains no `db.select` at all; and the ten-dep profile-import slice that `portability-runner.ts` passed TWICE (once to the portability descriptors, once to the hub) is built ONCE. **(7) RESERVED KINDS** (no owner yet) home at `domain/workloads/substrate/reserved-contributions.ts` — legal precisely because they carry zero domain knowledge (`reconcile-world-state`, blocked:PD-133). **(8) NEW-JOB COST: ~4 sites, three tsc-forced** — one tuple member + mode row (+ its params/result types) in contracts · ONE contribution in the owner's tree · one spread at compose (already covered if the owner has a factory) · the client's exhaustive Records. Down from ten across five tiers. **DEFERRED (report §5 stage E, tracked, none blocking):** the two-lane WORKER + the `workloads.lane` column (the lane axis is minted and every contribution declares one — `databank-ingest` is `interactive` — but the worker is still one global loop, so the head-blocking defect of §2 stands); the durable `progress` column; and the poison-row visible-surface fix (`toView` still drops silently). Landed: stages A–D, `pnpm check` PASS + `pnpm test` 8783/0 (CT 1827/0). **\[AMENDED STAGE E — the deferred substrate upgrades are BUILT; this clause CLOSES the DEFERRED list above]:** **(9) EXECUTION IS A LANE, ADMISSION IS A LOCK — and they never interact.** `workloads.lane` is a real column (CHECK derived from `WORKLOAD_LANES`, D34), stamped at the enqueue door from `contributions[kind].lane` (`start`; `retry` RE-stamps from the kind's CURRENT contribution — a lane is the owning domain's live declaration, not a property of the failed attempt). It is a COLUMN, never a claim-time derive, so lane assignment survives a restart. `nextRunnableWorkload` takes the lane and windows only that lane's queue head; the worker runs ONE poll loop per lane (`laneConcurrency`, a dep defaulted to 1 per lane — owner ruling on report §6 Q5: widening N is a dep, never a migration), sharing ONE boot/periodic reap and ONE wake subscription that resolves every sleeping lane. Each lane's loop stays sequential BY DESIGN; the parallelism is BETWEEN lanes. The §2 head-blocking defect is dead: a 20-minute `import-st` on `sweep` cannot delay a user's `databank-ingest` on `interactive` (regression-pinned with the sweep lane occupied by construction). Every single-active partial-unique index is untouched — locks admit, lanes execute. **(10) PROGRESS IS DURABLE, ON ONE WRITE PATH.** `workloads.progress` (JSON) carries the latest `WorkloadProgress`; `report()` records the snapshot and piggybacks the EXISTING heartbeat UPDATE, throttled to the same 5s lease cadence (`createLeaseWriter` — the heartbeat timer carries the latest snapshot too, so a chatty run costs the same db traffic as a silent one). The 60s in-process replay ring STAYS as the live-tail smoother; the ROW is the reconnect truth — `list` rows render real progress with no subscription open, which is what a tab opened 20 minutes into an import actually reads. The write is status-guarded like every lease write, so progress can never resurrect a terminal row. **(11) THE POISON READ PATH IS VISIBLE, NOT SILENT** (the on-record data-loss footgun, closed): `toView` surfaces a row whose params blob fails its contribution schema as `{…row, params: null, poison: true}` — `list`/`get` show a visibly-broken, cancel/RETRY-able row (retry clones the RAW blob verbatim through `loadRawWorkloadParams`, so the operator's original input survives into a build that fixed the schema). Only an UNKNOWN KIND still drops (deploy skew — it cannot be spelled). The DISPATCH path is correspondingly narrowed to a new `WorkloadRunnableRow` (the healthy case), and `nextRunnableWorkload` fails a poison head row in place: a row can be visible on the read surface and refused by the engine at the same time, by type. **(12) CLIENT:** the pane groups rows by lane (derived from the tuple; the heading is dropped when every row shares a lane — a lone group label is noise), renders the durable `progress` when no live tail is connected, and flags a poison row `Unreadable` with plain copy. **RESIDUALS from the stage-E list, verified already closed at stages A–D:** the dead `subscribeWorkloadEvents` front-door export (gone — the front door exports `subscribeWorkloadWake`, the worker's own seam) and the Constitution.md §6 indexer drift (fixed at D117's mint). **\[SCOPE ADDITION, owner ruling on report §6 Q4]: `stats.reconcile` is a direct tRPC mutation** — the already-proven awaited twin (`reconcileStats`, the same op the import post-settle calls) exposed as the instant "recompute my stats" on the Analytics dashboard. Owner-scoped by CONSTRUCTION: no id input, the rebuild scope IS `principal.userId` (swept EXEMPT with that reason). The `reconcile-stats` KIND stays for the all-owners BULK sweep — that is what the single-active lock + run history are for; `StatsService` gains its first write verb and `StatsContext` gains the injected clock.
