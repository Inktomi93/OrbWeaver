# Fleet out

## Goal

The engine-fleet launcher (spawn, stop, sleep, wake, reconcile, compose) and the model A/B harness move out of orbweaver into the owner's infra repo as a standalone package, and a fresh orbweaver clone typechecks, lints, passes `pnpm check` and its tests with no reference to either. The dev stack boots with no engine step; vLLM is a connection row, nothing more (owner ruling).

## Premises re-derived

- The brief said `serve.ts` in the A/B harness imports the fleet's argv builder. Refuted: the only mention is a comment; the real coupling is data. Most rows in the harness's variants.json point at the fleet's gen chat template by repo path.
- `packages/` reads neither ENGINES_POSTURE nor VLLM_DISABLED. Every pin of those keys in the stack scripts, the e2e modes, the snap stage, the multi-user fixture, the devcontainer, compose.dev.yaml and vitest.config.ts feeds only the fleet shell. Cutting them changes nothing the server sees.
- Nothing listens on the engine ports at design time, and the recorded identity file in the main checkout names engines from an earlier launch whose leaders are gone. There is no live fleet to hand over.
- The launcher on the current tree does not read the checkout's `.env`: the fleet env module parses `process.env` only. The owner's pinned VLLM_GEN_MODEL in the checkout's `.env` therefore reaches `pnpm engines` only when the shell exports it. The new home reads its own env file so the pin is honoured again.
- `@orb/tooling` exports are a `./*` wildcard, so removing the fleet directory removes no exports-subpath entry.

## Shape

Option (a): a standalone package at ~/inktomi-stack/vllm-fleet, moved mostly verbatim, with the orbweaver helpers replaced by one small vendored `_shared/` (a niced spawn door over `node:child_process`, a load-scaled `budget`, `runTool` and `UsageError`, the exit contract, `print`/`printResult`, `warn`, the engine port defaults). Node 26 runs the TypeScript directly, exactly as orbweaver does, so the package has no build step. Its only runtime dependency is zod; typescript and vitest are dev dependencies.

Layout of the new home:

- engines.sh, vllm-setup.sh, vllm-version.env at the root; engines.sh sources a gitignored `.env` beside it (the infra repo already ignores `.env` at any depth) and an `.env.example` documents every key.
- src/engine-fleet/\*\* (build-argv, env, spawn-engine, process-identity, proc-observe, reaper, fleet-control, fleet-metrics, wake-budget, gpu, engine-url, engines, index), src/engine-launch.ts, src/engine-adoption.ts, src/port-health.ts, src/spawn-lock.ts, src/types.ts (the engine slice of the old stack contract plus the ownership types), src/engines-compose.ts, src/\_shared/\*\*.
- ops/engines.ts, ops/engines-ctl.ts, ops/engines-compose.ts.
- templates/\*.jinja.
- compose.engines.yaml, regenerated by `bash engines.sh compose`, bind-mounting ./templates.
- model-ab/\*\* (cli, index, contract, lib, ops, variants.json) on the same vendored `_shared/`; variants.json points at ../templates/qwen3_gen_thinking_serve.jinja.
- tests/\*\* for the pure and process-level suites that port on vitest alone.
- package.json, tsconfig.json, vitest.config.ts, .gitignore (node_modules, .cache, reports), README.md.

Root and paths. The old code used `process.cwd()` as "repoRoot" for three things: the run dir (.cache/stack: pidfile, hold and stopped markers, logs), the chat-template directory, and the store root derived from the checkout's git common dir. In the new home the fleet root is the package directory (engines.sh runs node from there), the templates live at templates/ under it, and the store root is configurable: VLLM_STORE_ROOT, defaulting to the orbweaver checkout resolved relative to the package (../development/orbweaver), where .cache/vllm/venv and .models/hf already live. The identity file keeps its `repoRoot` field name so the record format is unchanged; its value is now the fleet root.

Posture. ENGINES_POSTURE had one reader left, engines.sh, and its only non-interactive callers (stack.sh, dev.sh) are cut. The verb `engines.sh start` keeps VLLM_DISABLED as the no-op switch and drops the posture vocabulary: `pnpm engines` typed by hand was always adopt-or-start, and there is no boot path left that must not spawn.

Compose. The generator keeps the same argv builder and the same launch-env refusal (a generated file must carry defaults, not one box's model path); it writes compose.engines.yaml at the fleet root and bind-mounts ./templates. The infra repo's own docker-compose.yaml can include it as an overlay when the owner wants containers.

What orbweaver keeps:

- The ENGINE_PORTS registry rows and the e2e harness's connection row at the generate port. The e2e suites adopt whatever engine the operator runs as a connection, and the stage bands must still clear those numbers. The rows are reworded as the operator's own engines; the registry no longer names a launcher or a pidfile.
- The dev-stack force-restart, minus the fleet half: it stops the stack and waits for the server and vite ports. The GPU-idle probe existed only to confirm the fleet's VRAM was released and leaves with the fleet.

## Rejected

- (b) Rewrite the launcher as bash/compose. The TypeScript is not mostly argv building: the argv builder is a small part beside the verified process identity (setsid group leaders, /proc start-ticks and cmdline checks before any negative-PGID signal, a per-launch marker for leaderless groups), a VRAM wake budget against foreign tenants, sleep/wake with hold and stopped markers, an orphan reaper and a sequential boot. The main checkout's last launch log shows that machinery working (a boot refused because another process held the card). Rewriting it in bash is a rebuild of paid-for safety with a fresh regression surface.
- (c) Leave the code in inktomi-stack importing orbweaver's tooling internals by relative path. The fleet would run on a private helper surface (proc, load-budget, run-marker, process-env) that orbweaver may change without notice, which is the design risk the brief names.
- Decouple model-ab and keep it in orbweaver. It boots the same vllm venv against the owner's quantized checkpoints, refuses to run while the fleet holds the GPUs, and most of its variants use the fleet's gen template. Keeping it means shipping an owner-box chat template in the public repo for one harness. It is fleet-adjacent owner tooling and moves with the same vendored helpers.
- Cut ENGINE_PORTS from the port registry. The e2e harness and the snap stage bands read the numbers, and the registry gate refuses a re-spelled literal. Rewording the rows costs one line each; cutting them costs a harness rewrite for no product change.
- Keep a `pnpm engines` alias in orbweaver that shells out to the infra path. It would be tracked orbweaver code naming the fleet, which the ruling forbids.

## Test plan

Red first, in the new home:

- The argv snapshot suite (build-argv) and the compose drift suite run against the moved sources with only their import paths rewritten. They are the same pins that guarded the launcher in orbweaver; a moved template path or a changed default reds them before any hardware is involved. Planted control: change one default in env.ts and watch the snapshot red.
- process-identity.int spawns real setsid children and proves the negative-PGID door still refuses an unverified group after the move.
- Static proof the brief demands: `bash -n` on both shells, `tsc --noEmit` over the package, `bash engines.sh compose --stdout` printing the overlay, and a regenerated compose.engines.yaml that matches the committed one byte for byte.

In orbweaver:

- tests/tooling/stack/\*\* after the cuts, tests/tooling/\_shared/ports.test.ts, tests/e2e/support/target-guard.test.ts, tests/tooling/verify/gates/tooling-front-door-family.suite.test.ts, tests/tooling/verify/ops/run.int.test.ts, tests/tooling/container-security-config.int.test.ts.
- `pnpm check` without LEFTHOOK_EXCLUDE, whose dangling-ref, port-registry, argv-front-door, slot-template, ledgers-fresh and agents gates are the backstop for a missed cite.
- The negative claim, rg over the tree for every moved basename and for ENGINES_POSTURE, engines.pgid, engines.stopped, engines.hold, wake-budget, buildEngineArgv, VLLM_ENGINES and model-ab, returning only docs/adr and docs/plans history.

## Owner forks

- The fleet's own `.env` in the new home is seeded from the VLLM\_\* lines of the checkout's `.env` so the pinned gen model is honoured again. Default: seed it; the file is gitignored there.
- The identity records left in the main checkout's .cache/stack name a dead launch. Default: leave them; the new home starts a fresh record under its own .cache/stack. If a fleet is ever running at merge time, stop it from the old checkout first.
- ENGINE_PORTS stays in orbweaver as the operator-engine reservation. Default: keep, reworded.
- The dev stack's healthz gate keeps its base although it was sized for a fleet cold-spawn during boot. Default: leave the number, fix the comment; perf work needs felt pain.
