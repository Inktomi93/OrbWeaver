# Repeat defects are closed by a type, then a rule, with every site at zero

## Goal

Each defect class that came back more than once is made unwritable: by the compiler where a type can carry it, by a lint or dependency rule where it cannot, and by a named test where neither can.

## Shape

One enforcer per leg, never two that touch the same files. Types first; a rule turns on with its sites at zero and no baseline, and ships with its law line. A brand mints at one named home. The enforcers: a required abort signal; row stamps from the injected clock; claim order as a token; a brand on member-facing text; a consenting-host brand for work on a host's account; a branded child-process environment behind typed launch doors; a truncated run that declares its reveal; author-keyed records with no index signature; a table registry that names each owning domain; a limited read that states a total order. Lint: no raw number coercion, a blind catch covers every constant answer, role comparison by type, tests that cannot fail, restated tuples in production, copy punctuation, and the listed configuration fixes. The source brief, with sites and patterns to copy, is in `reports/enforcer-brief/` on the owner's machine; its counts are a lead and each leg recounts on its own tip.

## Rejected

A custom gate script per defect: D333 removed custom gates, so the compiler and the native tools carry these.

## Coupled sites

The security legs (member text, consenting host, child environment, blind catch) go to the security role. The truncation leg follows the shared-owner work in the consistency plan, which changes the same primitives.

## Test plan

Each leg plants the wrong use and shows it fail the compiler or the rule before the drain lands; a type test holds each compiler enforcer.
