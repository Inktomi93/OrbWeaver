# One CSS system: ramps, aliases and a pinned owner-CSS surface

## Goal

Use one token vocabulary for application layout, primitive skins and appearance. Preserve supported owner styling and theme-relative paint.

The [implementation work](../../work/1299-build-the-css-system-ramps-conditions-locked-tsx.md) remains open. Source delivery and scoped acceptance do not complete its current-tree checks.

## Shape

### Standing constraints

- Derive ramp values from UI law: touch floors, density, reading measure, integer line boxes and the approved type hierarchy.
- Change a law-pinned value only with its reason, a stronger standard, the visible effect and the corresponding law edit.
- Keep semantic dimension tokens as aliases of their own primitive ramp. Structural geometry retains its documented exceptions.
- Name space, size and leading steps by their integer pixel value at the base root. Keep radius and type steps ordinal.
- Keep primitive variables private. Serve semantic variables independently of utility use.
- Reset governed Tailwind namespaces. Retained lint owns class vocabulary, arbitrary values, inline dimensions and built class strings.
- Features select primitive props and variants. Primitive skins remain in `@orb/ui` and resolve theme and appearance channels at their consumers.
- Use the typography voices in [UI-Density-Law](../../law/UI-Density-Law.md). A new voice requires a ruling.
- Keep Geist and Geist Mono as the shipped faces. `THEME_FONT_ALLOWLIST` owns selectable faces and derived fallback stacks.
- Keep the root font-rendering policy in [ui-package-design](../../law/ui-package-design.md). Its macOS appearance requires device review.
- Preserve theme-relative shadow ingredients under D200. Do not replace them with frozen colors or an independent elevation ramp.
- Preserve supported owner-CSS hooks and their application consumers, completion, warnings and injection rewrites.
- Preserve existing build generators, generated application contracts and useful native regression tests. D333 excludes an additional certification framework.
- Replace names and migrate consumers together. Add no compatibility aliases or unused condition vocabulary.
- Keep one condition vocabulary in tokens. The shell boundary includes 768px on the mobile side and preserves the ruled 1024px comparison.
- Keep capability and preference queries in the token, shell and primitive layers. Features adapt through container queries and primitive choices.
- Cap wide content by its measure. The composer and its adjacent bands must not exceed the transcript's reading column.
- Preserve `shell-short`: the room scrolls while controls remain reachable.
- Preserve the browser targets in `packages/client/browser-targets.ts`, including the Safari and iOS floor.
- Preserve safe-area, dynamic-viewport, overscroll, input-type and focus-zoom requirements through retained lint and stylesheet changes.
- Reduced motion, transparency and contrast support `system`, `on` and `off`. Explicit `off` overrides the OS preference.
- Preserve forward parsing of earlier boolean preferences. Boot replay and mounted writers use the same appearance channel names.
- Keep one typed appearance manifest. Numeric properties derive registration bounds and defaults from contracts; enum attributes remain explicit values.
- Keep appearance on the root and shell state at its own scope. JS-only settings declare that they have no CSS channel.
- Keep generated bytes under their generator's ownership. Fix generator output rather than broadening a lint exception for invalid output.
- Use before/after isolated captures and geometry checks for visible changes. Explain intentional differences and obtain rendered review.
- Do not add a committed screenshot regression corpus. Use the retained application instruments and native tests.
- Coordinate expensive runs under the lane and orchestrator skills. Do not generate artificial host contention.

### Styling and cascade

Keep the layer order in its source owner. A sheet that can load before the UI entry must import that order first.

Each authored sheet has one block per named layer. Keep root preference rules and descendant surface rules in their correct variant contexts.

Resolve glass, plates, shadow colors and carried-theme ingredients on the consumer. A formula resolved on the root cannot follow a nested theme.

Keep wallpaper-specific fade policy in client appearance and reusable masks in UI. Runtime image URLs, speaker colors and measured reservations remain runtime data.

Use logical box properties where platform support permits them. The panels retain physical `translateX` because FLIP owns the separate `translate` channel.

Owner custom CSS remains unlayered under the current design. Important declarations reverse layer rank; preserve the reduced-motion floor and its existing native tests.

### Feature className and chat skins

Feature classes express layout. Color, type, border, radius and shadow choices belong to primitive props or variants.

Chat skins remain a typed `ThemeChatStyle` table. The row components translate its track, alignment, box, header, action and swipe choices into primitive props.

The name row's bubble-ink rule belongs in client globals because it addresses chat-owned slots. It does not become a generic primitive skin.

Keep vendor CSS above preflight and below house layers. Preserve the justified Streamdown inline-style override and CodeMirror's runtime stylesheet behavior.

Preserve script sizing for Textarea where `field-sizing: content` is unsupported. Keep the same minimum and maximum rows.

Use supported overflow-axis spellings at the Safari floor. Unsupported scrollbar styling and off-screen skipping may fall back to browser defaults.

Avoid persistent layer-promotion hacks. Follow the integer-line-box compositing law and measure `contain`, `content-visibility` and backdrop-filter changes.

### Viewport and text scale

Conditions name layout facts, capabilities or preferences, never device classes. Tokens own their queries and generated `MEDIA_QUERIES` entries.

Preserve landscape access to the shell, room, composer and settings. Keep ultrawide content capped and hover actions usable without hover.

The root font size respects the browser default. Appearance font scale remains a multiplier; preserve the text-scale metadata and input zoom floor.

Dynamic Type remains deferred. Adopting `-apple-system-body` changes the approved iPhone type hierarchy and requires an owner decision after device review.

### Remaining acceptance

- Keep item 1299 open until its explicit current-tree native lint and dependency requirements are satisfied.
- Preserve the distinction between source delivery, selected rendered acceptance and full application CI.
- Qualify the unreached Import FormDialog before claiming its visual acceptance.
- Keep fine-pointer finder reveal-transition imagery unqualified. A recent-shelf focus image does not establish that behavior.
- Qualify topbar, panels and room at 200% text scale. Ambient-shell evidence does not cover them.
- Qualify 300% layout separately. Room measurements at the base scale do not cover enlarged text.
- Keep broader user text-spacing and zoom qualification separate from the scoped component evidence.
- Perform independent rendered review over the actual changed population. Main owns integration and shared verification.
- Keep real-device gaps open: notch insets including the bottom edge, keyboard with dynamic viewport, standalone status bar and theme color, rubber-banding and focus zoom.
- Keep Dynamic Type, Safari punctuation/pretty wrapping and macOS font rendering as device checks.
- Compare unreviewed legacy theme cases through the restoration register before adding tests. A missing reference suite is not permission to restore its old harness.

Playwright WebKit on Linux does not reproduce Safari's mobile chrome, physical safe areas, software keyboard, standalone mode or Dynamic Type.

RTL expansion is outside this assignment. A successful warm capture does not qualify cold startup.

## Rejected

- A second token vocabulary or hand-authored generated theme.
- Token values that change under stable pixel-step names.
- Compatibility aliases for renamed variables, utilities or primitive choices.
- An unused condition vocabulary or device-class breakpoint system.
- A hand-maintained styling inventory that duplicates generated application contracts.
- Reinstating custom certification, baseline or replay infrastructure excluded by D333.
- Treating an unbuilt user-CSS layer/versioning proposal or speculative analysis tool as approved implementation work.
