# Orbweaver — Path/Home Registry: D65

> Split-sibling of `Core-Laws-and-Precedents.md` §7 (range files D1–D61 listed there; D62–D65 solo). Decision **D65**: OIDC **group-derived roles** — admin is grantable by the owner *through the IdP* (`OIDC_ADMIN_GROUPS`) alongside `admin.setRole`; `OIDC_ALLOWED_GROUPS` is a fail-closed login gate; roles RE-DERIVE each login when group governance is active; the owner row is never group-derived, gated, or downgraded. **EXTENDS D17** (which said admin is granted ONLY by the owner via `setRole`).

---

- **D65 — Admin is grantable via owner-configured IdP group membership, not only `admin.setRole`.** Owner ruling (2026-07-10, verbatim intent): *"if a user is in my authentik and they sign in it will auto create; role in my mind is group based — I have Orb Admins and Orb Users."* The owner still fully controls the grant (they configure `OIDC_ADMIN_GROUPS` and manage the IdP's group membership) — so this is a NEW owner-controlled mechanism for the same authority D17 vests in the owner, not a delegation away from it. Reference model: OpenWebUI's `OAUTH_*_CLAIM` / `ALLOWED_ROLES` / `ADMIN_ROLES` (mapped onto orb's existing `USER_ROLES = owner|admin|user`; orb builds NO app-level groups/group-ACL/group-sync — YAGNI, no consumer). **The mechanism:**
  - **Role derivation** (`domain/sessions/substrate/role-policy.ts`): `determineRole` derives `admin` from `OIDC_ADMIN_GROUPS` (CSV) in addition to the existing owner-group path; a login carrying a matching group → `admin`, else `user`. Groups are read from the configurable `OIDC_GROUPS_CLAIM`, with NESTED dot-path support (`readClaimPath`, e.g. `user.memberOf` for Entra/AD FS/authentik) — a flat name stays a single-key lookup.
  - **Login access gate** (`deriveIdentityAccess`): `OIDC_ALLOWED_GROUPS` (CSV) — a user in NONE of the allowed groups → `{outcome:"deny"}`, **no JIT `users` row created**, seam returns null → **401** (distinct from `enabled=false` → 403). UNSET → all authenticated users allowed (legacy, backward-compat). **Fail-closed:** a missing/unparseable groups claim WITH the gate set → deny. Admin-group members BYPASS the gate (an admin always gets in — OpenWebUI parity).
  - **`ProvisionResult`** (`domain/sessions/contract/results.ts`) is now a discriminated union `provisioned | denied`; the OIDC route dispatches on it (mint session on `provisioned` gating `enabled`; 401 on `denied`). The entry/ route mirrors the shape structurally as a local non-exported `type ProvisionOutcome` (DI-port decoupling — no cross-tier import of the domain type).
  - **Re-derive-on-login:** when group governance is ACTIVE (`OIDC_ADMIN_GROUPS` or `OIDC_ALLOWED_GROUPS` set), role re-derives from groups on EVERY login — so an IdP group change (Orb Users → Orb Admins) takes effect next sign-in, AND a manual `admin.setRole` grant to someone NOT in an admin group is WIPED on their next login (intended — "role IS the group"). When NEITHER is set, no re-derivation: manual `setRole` grants survive (legacy behavior fully preserved).
  - **OWNER INVARIANT (absolute):** the owner is matched by the owner ROW id (`existing.id === selectOwnerUserId()`), NOT a role-literal compare (would trip `owner-role-split`) and NOT a policy/group match — so an owner whose IdP handle/groups no longer match `OWNER_*` is still protected. The owner is NEVER denied by the allowed-groups gate and NEVER re-derived/downgraded, even with empty or non-matching groups. The D17 single-owner enforcement (env `superRefine` + `reconcileOwnerSingleton` + `users_single_owner_unique`) is intact: group→`admin` can NEVER mint a second owner; a second policy-owner downgrades to `user` (least privilege), never `admin`.
- **Identity gained a nullable `email`** (`ResolvedIdentity.email`, `users.email` — baseline-squash regen) as a mutable ATTRIBUTE off the stable `users.id`; read from `OIDC_EMAIL_CLAIM` (default `email`) / `FORWARD_AUTH_EMAIL_HEADER`, persisted keep-on-null. Email is NEVER an identity/join key — identity stays keyed on `users.id` + `externalId`.
