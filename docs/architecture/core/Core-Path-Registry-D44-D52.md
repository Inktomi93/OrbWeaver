- **D44 — user theming + rich message content (CSS · HTML cards · inline images), redesigned to orbweaver rigor; specced BEFORE Phase 5 (2026-06-28).** Authoritative expansion: **`UI-Theming-and-Content.md` §12** (this entry is the decision record, that doc is the law). The SillyTavern expressive surface — custom CSS (global + per-character), rich HTML "cards", inline images — rebuilt so untrusted content is contained by **browser-enforced boundaries, not ST's bypassable regex-sanitize-and-scope** (verified from ST source `chats.js` `decodeStyleTags`/`addDOMPurifyHooks` + `power-user.js` `applyCustomCSS`: ST renames `.class`→`.custom-class`, prefixes `.mes_text`, strips `://`, DOMPurifies into the MAIN dom — clever but a denylist on a powerful language, and D21 "no leaks ever" rejects that posture). **Specced now because Phase-5 chat's message-content model, composer, and assembly DEPEND on it** — left unspecced, chat reinvents it (and copies ST). **Governing principle: two trust tiers, isolation by physics.** TRUSTED (owner global CSS / own persona theme / own uploaded images) = self-inflicted + design-integrity risk; UNTRUSTED (per-character CSS, card HTML, external image URLs, LLM markdown) = D21 security risk → contained by sandboxed-iframe / CSP / token-validation, never string-munging. **Decisions:** (1) **Theming scopes = Global(owner) + Per-character** (Nate; per-persona/per-chat deferred, resolution order `character > global > default` built to accept them). **Tier A theming = a curated Zod-validated TOKEN-OVERRIDE API** (accent/font-allowlist/bubble/bg/radius/density) applied as scoped CSS custom props via `@orb/ui` `<ThemeScope>` — values parsed+clamped at the boundary (reject `url()`/`expression()`), zero injection surface, stays in the DTCG token system; ST has no safe tier like this. (2) **Rich HTML: Tier A = inert sanitized allowlist via Streamdown** (its `rehype-raw`→`sanitize`→`harden` configured to OUR allowlist — structural/text/tables/details/lucide-icons/links/images; NO `<script>`/`on*`/`<style>`/inline-`style`/`<iframe>`/`<form>`), main DOM, covers ~90% of cards. **Tier B = `@orb/ui/sandbox-frame` (sandboxed iframe + per-frame CSP), opt-in per-character trust** — for elaborate self-contained HTML+CSS mini-UIs. **CORRECTION (research-driven): Tier B is a sandboxed IFRAME, not Shadow DOM** — Shadow DOM is encapsulation not isolation (JS gets full page access, `position:fixed` escapes, CSS `url()` still exfils, custom props pierce it, 2026 CSS-sandbox-escape CVE); a sandboxed iframe is a separate realm + per-frame CSP = the decade-proven primitive Claude Artifacts/CodePen/JSFiddle use for untrusted LLM HTML (ChatGPT Canvas refuses inline HTML entirely). render-on-complete (iframe enforces the streaming hold-back), inject theme tokens so `var(--accent)` tracks the theme, postMessage auto-height, lazy+virtualized (the one real cost, bounded to opt-in cards). **Interactivity DOORED not walled:** card JS/action-buttons (ST's QR/STscript) are a v1 NON-GOAL, but Tier-B-being-an-iframe means later = flip `allow-scripts` for a trusted card (the Artifacts experience), no re-architecture. (3) **Images + native media = two trust tiers too** (covers `<img>` AND native `<audio controls>`/`<video controls>` — verified from ST source: the "card generated an inline music player" was RAW HTML+CSS, a native `<audio controls>` element, browser-native controls = interactive with ZERO card JS; native media is the one HTML class that's interactive declaratively, sidestepping the no-JS rule). TRUSTED own-uploads → `assets` domain (4c) + `infra/image` sharp thumbnails (4b), `asset://id`, render freely (also the multimodal-send path); UNTRUSTED external URLs → **`forbidExternalMedia:true` by DEFAULT** (the load itself is the tracking-pixel/exfil — extends the existing D21 tri-state), click-to-load placeholder, **`autoplay` FORCED OFF + `controls` REQUIRED on untrusted A/V always** (an autoplaying untrusted `<audio>` is a tracking beacon + noise vector; ST forces `autoplay=false;pause()`, we harden it non-overridable), `allowedMediaPrefixes`+`allowDataImages:false`+CSP `img-src`+`media-src` backstop when permitted; `@orb/ui/MessageMedia` (img+native a/v · asset-vs-external dispatch · lazy · aspect-reserve · autoplay-off · fallback · lightbox). (4) **Message-content model (`@orb/contracts`, born-compliant): a typed `MessageContentBlock` union** (`markdown | image{src:AssetRef|ExternalUrl} | html-card{html,css?,trust}`), NOT ST's one-HTML-string — must land in the contracts pass, chat assembles it (`override ?? global`). **New gates:** `no-untrusted-html-in-main-dom` (untrusted HTML reaches ONLY `sandbox-frame`), `no-external-media-without-gate` (external `<img>/<audio>/<video>` only via `MessageMedia` + forced autoplay-off), `theme-override-only-via-scope`, CSP-headers-present test, extend `no-raw-value`/no-inline-`style` to message render. **Homes:** contracts (`ThemeOverride`/`MessageContentBlock`) · `@orb/ui` (`ThemeScope`/`sandbox-frame`/`MessageMedia`+lightbox) · `@orb/ui/markdown` (Tier-A allowlist) · assets+infra/image · chat (composer attach/multimodal/override-resolution, P5, extends D21) · entry/http (CSP). **Born-compliant sequencing:** the `@orb/ui` primitives + the contracts model + CSP + the gates ship in the `@orb/ui`/contracts passes BEFORE Phase 5 wires chat content (same rule as §11.7); assets(4c)+infra/image(4b) are prereqs already in plan.
