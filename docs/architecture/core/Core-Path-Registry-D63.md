# Orbweaver — Path/Home Registry: D63

> Split-sibling of `Core-Laws-and-Precedents.md` §7 (range files D1–D61 listed there, D62 solo). Decision **D63**: the app background IMAGE re-homes from the theme to the user appearance namespace.
> **Audited 2026-07-09 (tree @ ec937b1):** every entry's path/home/enforcement claims verified against the code — ALL LIVE, no supersessions beyond those already annotated inline (fully built: the image fields are gone from `contracts/theme/override.ts` + the ui clamp, and live in the appearance namespace).

- **D63 — The app background IMAGE moves from `ThemeOverride` to the `appearance` user-settings namespace (2026-07-07). AMENDS D49 §3.** D49 §3 homed the app-chrome background as a `ThemeOverride.background` token (image + fit, per-user global). In build it split correctly into two concerns — the base surface **COLOR** (`background`, which feeds the neutral ramp via `oklch(from background …)`) and the decorative **PHOTO** trio (`backgroundImage`/`backgroundFit`/`backgroundDim`, a fixed-position app-root `<ThemeBackgroundLayer>` + mandatory scrim, never a `--*` var). Shipping it revealed the photo-on-the-theme home is wrong: (1) it's **undiscoverable** — buried in the theme-*editor* entity, disconnected from the glass toggle it pairs with; (2) it's **coupled to the palette** — set a photo on Mocha, switch to Hearth, it vanishes; (3) a built-in (seed) theme can't take one without duplicate-to-customize. A background photo is a **palette-independent user choice** (the ST/Marinara model — backgrounds are their own thing), so it belongs on `appearance`, not the color theme. **The move:** the base surface **COLOR stays** a `ThemeOverride` token (ramp-load-bearing); the **IMAGE trio moves** to `@orb/contracts/settings` `appearance` as **FLAT fields** (`backgroundImageKind: none|seeded|external` · `backgroundSeededId` · `backgroundExternalUrl` (URL-validated → CSS `url()`) · `backgroundFit: cover|contain` · `backgroundDim: 0–1`) — flat, not a nested union, to fit the all-flat appearance namespace + its autosave-form binding. The picker lives in the **Appearance settings pane** beside the glass/`blurSurfaces` control (the two compose — glass has nothing worth blurring without a background). Applied once at the app root (`<ThemeBackgroundLayer>` reading `appearance`), so a nested per-speaker `<ThemeScope>` never spawns a second layer. **Per-character background is DROPPED from scope** (it was unreachable — no character editor exists yet, and D49 already cut the VN scene-compositor); re-addable later as an override layer if wanted. **Touched:** `contracts/theme/override.ts` (drop the trio + `THEME_BACKGROUND_FITS` + the source union; keep `background`), `contracts/settings` (add the flat fields), `@orb/ui` `theme-scope/clamp.ts` (drop the trio + `ThemeScopeBackgroundImageSource` — the image leaves the ui entirely), the app-shell render (read `appearance`), the theme-editor (picker removed) + the appearance pane (picker added), and the contracts↔ui pairing test. `asset` source stays deferred (#67/PD-131 — no client asset-URL resolver). (Nate — reported the background undiscoverable + glass invisible; chose the user-appearance home over keep-on-theme, 2026-07-07.)
