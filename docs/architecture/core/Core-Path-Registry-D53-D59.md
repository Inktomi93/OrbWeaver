- **D53 — Regex scripts: three sources via joint attachment, a HOST-authority (shared, server) vs PER-USER-display (ephemeral, client) precedence split, and the `node:vm` ReDoS watchdog homed in `@orb/server/kit` (2026-06-29).** The regex ENGINE is already built (`@orb/kit/regex` — all 5 placements `USER_INPUT`/`AI_OUTPUT`/`SLASH_COMMAND`/`WORLD_INFO`/`REASONING`, captures, the `applyReplace?` seam, the pre-compile heuristic; `RegexScript` in `@orb/contracts/regex` carries the `markdownOnly`/`promptOnly` flags); what was unsettled is the SCRIPT-ATTACHMENT MODEL + precedence + the ReDoS guarantee. Decided (Nate blessed): **(1) Three sources, joint-attached (the WI-book / tag-junction pattern, D24 — no polymorphic):** **per-character** (already live — flat `characters.regexScripts: RegexScript[]`, D28), **preset-embedded** (the active preset carries a script set, like its other config), **global** (the owner's single-owned set — `fetchOwned`). A chat's EFFECTIVE host-tier set = host-global ∪ chat-preset ∪ the cast characters' scripts, resolved under the frozen `runAsUserId` (D19) at SEND/RECEIVE. **(2) Precedence = the established host-authority model (D18/D22):** anything that mutates the SHARED prompt or canon — `USER_INPUT` (send), `WORLD_INFO` (assembly — already wired), and the persist-/`promptOnly`-affecting `AI_OUTPUT`/`REASONING` (receive) — is **HOST-OWNED, shared, server-side** (one shared prompt → one authority, exactly like the host owns the preset / WI / room-overrides / member-card visibility). A non-host member contributes **NO** shared-prompt regex. **(3) Per-user display regex is the ephemeral half:** a user's **`markdownOnly` (display-only)** scripts run **CLIENT-SIDE, per-user, ephemeral** — they transform only what THAT user sees, never canon or the shared prompt (the D44 render-tier model). So a **view-only** member in a group chat still gets their own display regex working locally, with zero authority risk (it cannot reach shared state). The `markdownOnly`/`promptOnly` flags ARE the prompt-vs-display discriminant: `promptOnly`/persist-affecting → host/server tier; `markdownOnly` → per-user/client tier; default (both) splits across the two. **(4) The ReDoS watchdog respects the isomorphic boundary:** `@orb/kit` is isomorphic (bundled to the browser too), so `node:vm` MUST NOT live there — kit holds only the `applyReplace` SEAM + the native-`replace` default ("the browser's lot") + the pre-compile heuristic (defense-in-depth ONLY — it counts quantifier-stack occurrences, so the canonical `(a+)+` passes it; NOT a guarantee). The real guarantee is a **`node:vm`-sandboxed `applyReplace` with a hard per-call timeout**, homed in **`@orb/server/kit/regex`** (server package, never browser-bundled — currently a one-line placeholder), injected through the kit seam at turn time; a runaway pattern throws → `onScriptFailure` instead of hanging the event loop. **Build sequence (a hard order):** build the `server/kit/regex` watchdog FIRST → then wire `executeRegexScripts` at the SEND (`USER_INPUT`) + RECEIVE (`AI_OUTPUT`/`REASONING` + `<think>` parse) seams host-side WITH the watchdog injected (wiring the native default at the user-regex execution point would ship the ReDoS hole live) → reserve the per-user client-display layer for Phase 6. **Homes:** `@orb/contracts/regex` (`RegexScript` — DONE) · `@orb/kit/regex` (engine + seam — DONE) · `@orb/server/kit/regex` (the `node:vm` watchdog — TO BUILD) · `@orb/db` (the global-owner + preset-embedded script homes; per-character DONE) · `domain/chat` engine RECEIVE + send-verb SEND (the wiring) · `client` (the per-user `markdownOnly` display layer, Phase 6). (Nate — "global / preset / per-character… joint like tags or WI… host stuff applies over others… view-only ephemeral stuff applies for them on their client"; blessed.)
