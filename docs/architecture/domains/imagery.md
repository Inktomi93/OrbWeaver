## 0. Naming

Domain is `domain/imagery`. "studio" implied a client UI surface; the concept here is a server-side
**orchestration leaf** — turn chat/character context into a generated image, store it, hand back a render
block. The `/imagine` command, settings panel, and gallery are _clients_ of this domain, not the domain.

---

## 1. What it is

A **leaf domain** (8-slot template) sitting atop three existing orbweaver seams:

- `generateImage` role (D39 — hosted-only)
- `assets` CAS (D21)
- `MessageContentBlock`/`MessageMedia` render model (D44)

It owns the **prompt-template orchestration** (mode → LLM extract → generate → store → block) and nothing
else. It has no DB table of its own — generated images land in `assets`, messages in `chat`.

### Provider roles used

- `generateImage` — the text→image / edit call (hosted-only, D39)
- `chat` or `summarize` (shaper) — the quiet LLM extraction call (the two-step, step 1)
- Vision/caption op (D45/D47-6) — for multimodal modes

---

## 2. The ST source (what we modernize, not port)

ST's `stable-diffusion/index.js` (5998 lines) does 5 jobs; only 3 are in scope:

### 2.1 Prompt-template modes (the core two-step)

**Mode enum** — `CHARACTER` (full body), `FACE` (close-up), `SCENARIO` (whole scene), `BACKGROUND`
(environment), `FREE` (user literal text, no extraction), plus multimodal variants that caption the avatar
via vision rather than extracting from text.

**The extraction call** — a quiet (non-posted) LLM completion shaped by the mode template; reply is
`processReply`'d (strip quotes/newlines→commas, NFD normalize, alnum+SD-syntax filter). FREE skips it.

**Then generate** — prepends a character-specific prompt prefix (FREE/BACKGROUND skip it), applies
type-specific dimensions (FACE → portrait, BACKGROUND → landscape), calls the generateImage role, posts
result as a `MessageContentBlock`.

### 2.2 img2img / hosted image EDIT

ST's img2img/inpaint is local-SD only. On a hosted-only stack the equivalent is **image EDIT** — pass an
init image (+mask) to a capable model (gpt-image-1 edit, Gemini image editing). Shape mirrors D45's vision
input.

### 2.3 `/imagine` surface

`/imagine` is a **`domain/automation` Tier-1 action** (D46), NOT a bespoke command engine. Args reduce to
hosted-relevant set: `mode`, `negative`, `prompt`, `n`, `size`, `quiet`. Local-SD knobs die with D39.

## 4. Home in the cake

### 4.1 `domain/imagery/` — 8-slot template

```
domain/imagery/
├── index.ts          FRONT DOOR — ImageryService interface + createImageryService
├── service.ts        COMPOSITION ROOT — wires verbs + injected cross-feature ops. Zero logic.
├── context.ts        DI BUNDLE — { resolveRole, generateImage, extractPrompt,
│                       captionImage, storeAsset, transformImage?, clock }
├── contract/
│   ├── service.ts    interface ImageryService
│   ├── params.ts     GeneratePictureParams · ExtractPromptParams · EditImageParams
│   ├── results.ts    GeneratedPicture (assetId + MessageMedia-ready block + provenance)
│   ├── views.ts      (thin — result IS a contracts MessageContentBlock)
│   └── errors.ts     ImageryNotConfiguredError · PromptExtractionFailedError · GenerationFailedError
├── verbs/
│   ├── generate-picture.ts   orchestrator: mode→template→extract→generate→store→block
│   ├── extract-prompt.ts     mode-template → quiet LLM call → processReply (step 1)
│   ├── caption-avatar.ts     multimodal: avatar bytes → vision caption → prompt
│   └── edit-image.ts         img2img/edit: init image (+mask?) → generateImage(edit) → store
├── persistence/      (NONE — documented-empty slot; imagery owns no table)
└── substrate/
    ├── templates.ts  PROMPT_TEMPLATES keyed by PromptTemplateMode (Record<Mode,string> → tsc enforced)
    ├── mode.ts       PromptTemplateMode union helpers (FREE detection, trigger→mode)
    └── process-reply.ts   processReply (pure: strip/normalize the LLM keyword list)
```

**Why a leaf and not part of `chat`:** cross-feature by construction (needs `chat` role, `generateImage`
role, and `assets`). A leaf that injects all three at the composition root keeps `domain-no-cross-feature`
true. Mirrors how summarize/translate are "shapers over a role."

**No DB table.** Generated images → `assets` rows. Chat message → `message_variants` (D44). Imagery is
pure orchestration; `persistence/` slot is documented-empty.

### 4.2 `@orb/contracts/imagery`

- `PROMPT_TEMPLATE_MODES` tuple + `promptTemplateModeSchema` + `PromptTemplateMode`
- `generatePictureRequestSchema` (mode, optional override prompt, negative, n, size)
- Result is a `MessageContentBlock` — re-exported, not redeclared

### 4.3 `infra/providers` — `ImageGenerateRequest` widening

```ts
export interface ImageEditInput {
  readonly image: Uint8Array | string; // bytes → data-URL; string → URL/data-URL
  readonly mask?: Uint8Array | string | undefined;
}
export interface ImageGenerateRequest extends RoleRequestCommon {
  readonly prompt: string;
  readonly systemPrompt?: string | undefined;
  readonly n?: number | undefined;
  // NEW (additive, optional):
  readonly negativePrompt?: string | undefined;
  readonly size?: { readonly width: number; readonly height: number } | undefined;
  readonly edit?: ImageEditInput | undefined; // present ⇒ img2img/edit; absent ⇒ text→image
}
```

A model that can't edit drops `edit` with a `warning` ChatEvent (the D45 `image_dropped` precedent).

## 5. Cross-feature injection model

All wired at `entry/compose` — imagery sideways-imports nothing.

| Op                                 | Provided by                    | Purpose                       |
| ---------------------------------- | ------------------------------ | ----------------------------- |
| `resolveRole("generateImage")`     | `domain/connection`            | resolve hosted source+model   |
| `generateImage(req)`               | `infra/providers`              | the text→image / edit call    |
| `extractPrompt(quietPrompt, ctx)`  | `domain/chat` summarize shaper | LLM keyword-list extraction   |
| `captionImage(bytes, instruction)` | D45/D47-6 vision op            | multimodal modes              |
| `assets.store(bytes, kind, mime)`  | `domain/assets`                | persist bytes to per-user CAS |
| `transformImage` (optional)        | `infra/image` (sharp)          | thumbnail/resize              |

**Consumers of imagery** (injection only — never import internals):

- `domain/chat` (or turn pipeline) injects `imagery.generatePicture` for chat-turn image attachment
- `domain/automation` Tier-1 "trigger a generation" action calls `imagery.generatePicture` via injection
  (this IS `/imagine` and rule-driven generation — one path)

## 6. Contract shapes

### 6.1 Mode union

```ts
export const PROMPT_TEMPLATE_MODES = [
  "free",
  "character",
  "face",
  "scenario",
  "background",
  "character_multimodal",
  "face_multimodal",
] as const;
export const promptTemplateModeSchema = z.enum(PROMPT_TEMPLATE_MODES);
export type PromptTemplateMode = z.infer<typeof promptTemplateModeSchema>;

export const generatePictureRequestSchema = z.object({
  chatId: typeIdSchema(ID_PREFIX.chat),
  mode: promptTemplateModeSchema,
  prompt: z.string().optional(), // override/edit prompt; required when mode==="free"
  negative: z.string().optional(),
  n: z.number().int().min(1).max(4).optional(),
  size: z.enum(["square", "portrait", "landscape"]).optional(),
  quiet: z.boolean().optional(), // don't post to chat, just return the block
});
```

Templates in `substrate/templates.ts` as `Record<PromptTemplateMode, string>` (→ new mode fails `tsc`).
Macro-substituted via `kit/macro` (`{{char}}`/`{{user}}`).

### 6.2 Service interface

```ts
export interface ImageryService {
  generatePicture(p: GeneratePictureParams): Promise<GeneratedPicture>;
  editImage(p: EditImageParams): Promise<GeneratedPicture>;
}
export interface GeneratedPicture {
  readonly assetId: AssetId;
  readonly block: MessageContentBlock; // {kind:"media", media:"image", src:{kind:"asset",assetId}, …}
  readonly prompt: string; // resolved prompt (provenance / "regenerate")
  readonly model: string;
  readonly costUsd: number | null;
}
```

## 8. Open questions (resolve before build)

1. **Quiet-extraction provenance.** Does the extraction turn count against the chat's budget/attribution? Proposed: yes — bill to the initiating principal, don't persist as a visible message.
2. **Chat role vs summarize shaper for extraction?** Proposed: shaper over `summarize` role config so users can point extraction at a cheap model independently.
3. **Hosted img-EDIT gate.** Need a `ModelCapability` axis (like D45 vision) to gate `edit` vs drop-with-warning. Reuse/extend D45.
4. **BACKGROUND mode destination.** No per-chat background in orbweaver (gap §6 out). Proposed: generate and post as a normal media block.
5. **`n > 1` → one message with n media blocks, or swipe variants?** Proposed: n blocks in one message (D44 block array).
