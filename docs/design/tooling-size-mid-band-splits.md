# Tooling size splits — the 480–900 line band (17 modules)

> The design record for decomposing the seventeen `@orb/tooling` modules the `tooling-size` gate (`Core-Tooling-Law.md` §4.3, hard cap 450) reported between 480 and 900 lines on 2026-09-18 (structure run slot `agent-aeb9f3c2cb4b24dd9-3629480-2026-09-18T15-20-10-441Z`, 30 findings, 17 in this band). Each cut is one seam by NATURE (§9.1 of the tooling law), the original module stays the live front door, and the extracted half is a strict leaf the original imports. This doc carries the four laws that shaped every cut, the per-module seam table, the alternatives that were rejected, and the coupled sites. The WHY of each individual seam lives in the new module's header.

## 1. The four laws that decided the shape (receipts)

1. **A value re-export is biome-RED in every non-barrel module.** `biome.json:311` sets `lint/performance/noBarrelFile: "error"` and only `tooling/src/*/index.ts` (`:441`) and `tests/**` (`:678`) turn it off. Probed 2026-09-18 with a scratch `lib/` file carrying one `export { x } from "./y.ts"`: biome exit 1, `lint/performance/noBarrelFile`. `export type { … } from` is not flagged. So the brief's "re-export from the original for backward compat" is realizable only for types; a moved VALUE either keeps its consumers untouched through a delegating function in the original (the `b87f50689` `variant-matrix.ts` → `variant-matrix-engine.ts` precedent) or its consumers repoint to the new home.
2. **No import cycle, type-only included.** `.dependency-cruiser.cjs:78` extends `dependency-cruiser/configs/recommended-strict`, whose `rules/no-circular.cjs` is `to: { circular: true }` with no `viaOnly`/`dependencyTypesNot` exemption — an `import type` back-edge is a cycle. Every sibling below is therefore a LEAF: the original imports the sibling, never the reverse. Where a leaf needed a symbol the original also exports, the symbol moved DOWN and the original became its importer (never a re-exporter — law 1).
3. **No new exported `type` alias in `lib/` or `ops/`.** `no-inline-types` (`tooling/src/verify/gates/no-inline-types.ts:136-147`) judges `@tooling` minus `tooling/src/_shared/**` and `**/contract/**`, and flags exported TypeAliasDeclarations (`:110-113`), never interfaces. Every shape a sibling exports is an `interface`; the one intersection alias (`config-snapshot.ts` `NativeEslintConfig`) stays module-private inside its new home.
4. **Pinned capabilities do not move.** `lib/reviewed-grants.ts:2898-2905` licenses `tooling/src/verify/lib/baseui-read.ts` for `ts-morph-project-construction` (both `new Project(` sites stay there, per the `proc.ts` #2242 precedent: only non-capability code may leave a grant-pinned module); `gates/policy-legacy-imports.ts:157-167` fences gates from `lib/ordinary-waiver.ts` (the engine, its marker grammar and `createOrdinaryWaiverEngine` stay; the sibling holds no marker parser and no verdict); `gates/tooling-ops-direct-invocation.ts:92` makes every `ops/*.ts` owe `refuseDirectInvocation` (the new siblings under `ops/` are none — pure halves went to `lib/`); `Core-Docs-Formatting-Law.md:17` names `doc-catalog/ops/format.ts` the ONE markdown writer (the remark processor and `writeFileSync` stay).

Consumer rule derived from laws 1–2: a moved export with ZERO external importers just moves; with ≤ 3 cold importers (a test, a `index.ts` barrel line, one lib or one gate) the importers repoint; with a hot fan-out (many gate files) the original keeps a one-line delegating function under the same name, importing the implementation under an alias. Every sibling exports exactly what its importers consume (knip's unused-export arm is the fence).

## 3. Rejected alternatives

- **Re-export barrels in the original** — law 1; the brief's step 6 is unrealizable for values and the `b87f50689` precedent already answered it with delegations.
- **Types-vs-runtime cuts** — the `verify/` tool already homes its shapes in `verify/contract/*` (a twin `contract/<name>.ts` exists for most of these readers), so the runtime module holds no type half worth a file; the honest seams are runtime-vs-runtime by concept.
- **Cutting the acquisition half out of `baseui-read.ts`** (the fs half the header says only two callers use) — the two `new Project(` sites are grant-pinned by file (law 4).
- **Cutting `parseMarker`/the outcome table out of `ordinary-waiver.ts`** — a gate importing the sibling would then hold a marker parser, the exact capability `policy-legacy-imports` fences; the carrier readers are geometry and carry no exemption power.
- **One sibling for `knob-wire-fact.ts` and `policy-descriptor-read.ts`** — the largest coherent section of each (214 and 231 lines) leaves the original over the cap; a single ≥ 380-line sibling would itself sit at the cap and merge two concepts.
- **Type-only back-edges to keep a symbol's home** (`ChatPlaneIndex` in a reach sibling, `AcquiredMarker` in a binding sibling, `SheetCensus` in the seams module) — law 2.
- **Threading `MATRIX_CONST` by moving the whole chat-plane vocabulary into the matrix module** — it would split a family's constants across two homes for one refusal-message name; the fold takes the subject name as a parameter instead.

## 4. Coupled sites

- `tooling/src/verify/index.ts` barrel lines: `BASE_UI_MODULE_PREFIX` → `lib/baseui-surface-derive.ts`; `executePolicyPlan` → `lib/policy-plan-execute.ts`.
- Repointed consumers (all single import lines): the three `lexicalReferenceSymbol` importers; `gates/{diagnostic-legibility,policy-soundness,policy-waiver-identity,policy-waiver-spelling,policy-proof-expectations,policy-family-readers}.ts`, `ops/new-gate.ts` and `tests/tooling/verify/lib/policy-descriptor-read.test.ts` for the static-text names; `gates/seed-theme-ink-contrast.ts`; `tests/tooling/_shared/load-budget.test.ts`.
- Prose pointers that name an ORIGINAL by path stay true by construction: `gates/baseui-surface-manifest.ts:144,147` (`installedPackageRootOf` stays), `gates/chat-viewer-plane-canon-reads-health.ts:52,90` (`BULK_CANON_READERS` stays), `docs/design/1208-instrument-substrate.md:413,424` (every listed `load-budget.ts` export stays), `docs/design/951-css-family-semantic-provenance.md:66` (the report arms stay), `Core-Docs-Formatting-Law.md:17`.
- `tests/tooling/verify/gates/mirror-index-family.suite.test.ts:518` records that no `bus-fact-relay.ts` exists — the emission sibling is deliberately not named `bus-fact-relay.ts`.
- `Core-Tooling-Law.md` §2.4's `_shared` table is a roster of plumbing CONTRACTS, not of files (`browser-capture.ts`, `variant-matrix-engine.ts`, `proc-contract.ts`, `run-retention.ts` are absent from it today); the two new `_shared` siblings are implementation halves of listed rows and add no row.
