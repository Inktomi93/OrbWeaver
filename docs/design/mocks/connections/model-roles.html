The readout has FOUR arms, and only the first two share a condition. Board A renders every one of them, so step 9 does not build two and let the other two fall back to a sentence that is false:

  1. steady (.readout.steady) — a connection is bound and a turn would run on it: “A turn uses X.”
  2. divergence (.readout.drift) — the picker's selection is not the persisted read, info colour: “Not applied yet — a turn still uses X.”
  3. unset (.readout.none) — nothing is bound, italic muted: “Nothing — no connection is set.” The dot is a ring.
  4. blocked (.readout.blocked) — a connection IS bound and a turn would not reach it, warning colour: “Set, but not running — can't reach 127.0.0.1:8000.” It repeats the dot's own accessible name word for word, which is what makes the amber dot decidable without colour. An earlier draft wrote this arm on .readout.steady and phrased it “A turn uses nothing — Can't reach … — the server may be down.”: two stacked em-dash clauses, and “uses nothing” parses for a beat as uses [the thing called] nothing.

The two-arm pair's condition is draft-vs-persisted, not request-in-flight. Steady state reads “A turn uses X.” — the string that ships. It is divergence that gets §5.3a's sentence: “Not applied yet — a turn still uses X.”, in the info colour, when the picker's selection is not what the persisted read returns. Why the condition matters: a busDriven write reconciles through the bus, so between its 200 and the bus tick the read still serves the PRE-write row, and a surface keying its honesty on request state calls a saved selection unsaved for the length of that window (tests/client/data/_ct-stories.tsx:690-696, the createEntityMutation echo seam that closes it). The 2026-08-01 incident — two hours of a NULL value under a “Saved” chip — is why the divergence signal has to exist at all; echo is why it can key on the draft without lying.

The readout names the connection in the SAME words as the control 40px from it. An earlier draft read A turn uses openrouter · anthropic/claude-opus-5. beside a picker reading OpenRouter · Claude Opus 5 — the registry id and the raw model id against the connection's label. The readout's entire job is COMPARISON (is what a turn uses the same as what I picked?), and two vocabularies make that a translation exercise; it is also exactly the class §5.3a's Words paragraph exists to kill, since provider is a user-facing label and not a lowercase registry id. The counter-argument — that the label is user-editable, so the ids are the honest truth about what will run — does not survive §5.3a's own rule for labels: label auto-mints <provider> · <model> and is collision-suffixed, so it identifies exactly one connection by construction. The machine ids stay where a person goes when they want them: the editor's Essential tier.

Requirement badges are per-CLAUSE, and only where a clause exists. They render requirementMet's verdict (packages/contracts/src/inference/capability/reads.ts:110), whose missing names each unmet clause in axis:member spelling precisely so a surface can say “captioning needs image input” instead of failing at the wire. Chat, Image generation and Rerank have no requires block worth showing a user — Chat has none at all — so they show no rail. The Utility row shows three because its slot is three tasks: summarize (prose), the structured task that rides its binding (structured JSON), and captions (image input). That is the whole reason the row was renamed: a user who reads “Summarize” and binds a cheap text-only model silently breaks captioning and extraction, and the badges are what make the third consumer visible before the binding is written.

The refusal is stated TWICE on purpose and they are not duplicates. In the picker it is the option's own disabled reason — the sentence connections-model.ts::bindRefusal already returns — so a user scanning the list learns why a row is unpickable without picking it. In the row it is the REPAIR: the same sentence plus the switch that resolves it, because §5.3a makes the slot the first enforcement point ("so the user learns at authoring time") and a refusal with no adjacent remedy sends the user to the connection list to find a switch they have not been told the name of. The switch here writes the same allowBackground field the list row's switch writes, and the mock spells it the same way on both surfaces for exactly that reason. Resolve's canFund still re-checks — the flag can flip after the binding is written — so this is the friendly gate, never the only one. The two failures stack without merging. Background-work-off is a REFUSAL (the binding cannot be written); a missing image input clause is a PARTIAL (the binding is legal and one of the slot's three consumers will skip). Rolling them into one warning would make a fixable block look like an unfixable one; keeping the badge rail and the refusal box separate is what lets the user see that turning the switch on gets them two consumers out of three.

Board D — what the status dot means

the per-role dot
Running. A turn you trigger for this role would run right now, on the connection named in the readout.
Set, but not running. A connection is bound and a turn would NOT reach it — the readout says why, in one sentence, from the same cause the resolver returned (unreachable, the key was revoked, the connection was removed, the pick has not applied yet).
Not set. Nothing is bound. For an optional role that is a choice, not a fault — which is why the empty dot is a ring, not a red disc.
and what it deliberately does NOT mean
A failed requirement is never the dot. The dot has one axis — would a turn run — and a requirement failure is a different question with a different answer per clause. A bound model that cannot read images still RUNS; two of the Utility slot's three consumers work and captioning skips. Colouring the dot amber for that would say the role is broken when it is partly working, and it could not say which part.
The dot is never the only signal. It is a scanning aid over six rows; the sentence beside it is the answer. Every state above is fully readable with the dot removed, which is also what makes it safe against colour-vision loss and against a greyscale render.
