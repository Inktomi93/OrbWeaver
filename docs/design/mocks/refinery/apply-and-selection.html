Refinery — selection scope, the accept set, and what apply refuses

Three states that only exist because the shipped verb made them granular: the session selection (refinerySelectionSchema {fields[], greetingIndexes?}), the accept set the user hands to applyFields, and the itemised drop result the belt-9 fence produces. Every drop reason drawn below is a real member of ApplyDropReason — the UI's job is to say each one in English, because a silent drop reads as data loss.

LAW The field list, its ORDER and its spellings are REFINABLE_FIELDS verbatim (canonical-card order): description · personality · scenario · greetings · exampleMessages · systemPrompt · postHistoryInstructions · depthPrompt · creatorNotes. No "alternate greetings" row exists — orb folds greetings into ONE index-addressable array, and per-slot granularity rides greetingIndexes. That is why the greetings row is a tri-state parent with an index list under it, not nine sibling rows.

LAW greetingIndexes absent means EVERY greeting. So an all-checked greetings parent must save as absent, not as [0,1,2,3] — otherwise a greeting added later silently falls outside the session's scope. The UI must not make that distinction visible, but the build must honour it.

LAW depthPrompt means the note TEXT only; the {depth, role} directive is authored config the model never rewrites. A card with no depth note gets the DISABLED row drawn above rather than a hidden one — apply would drop it as not_applicable anyway, and a checkbox that leads to a drop is a trap.

FORK F · default selection Drawn: "populated fields" (the shipped startSession default) with greetings ALL in scope. The alternative is "everything the score marked below 7" — a quality-driven default that makes the first run cheaper and more targeted. Rec: keep populated-fields as the born default (it needs no prior score), and add a "Select what scored under 7" action to the scope editor once a score run exists. Drawn as the "Reset to populated" slot's sibling — the owner decides whether that second action ships in R3 or R4.

FORK G · where the scope editor lives Drawn as a panel (the CONTENT "Edit scope" affordance opens it). Alternatives: a permanent left column inside CONTENT (always visible, costs ~260px), or a CONTEXT tab. Rec: panel-over-CONTENT as drawn — CONTEXT is ruled to carry cross-run cargo only, and a permanent column starves the assay at the narrow desktop mount.

Frame 2 — the apply result: 3 applied, 3 dropped, each with its reason

This is the frame the granularity exists for. applyFields never refuses a whole payload — it applies what survives the belts and itemises every drop. A UI that only says "3 fields applied" throws away the half of the result that tells the user something went wrong.

The card's depth note has been removed. The rewrite only carries the note's TEXT — it cannot invent the depth/role directive.

LAW The six reasons are the closed ApplyDropReason axis, and each needs its own English: not_in_rewrite · not_selected · greeting_index_missing · greeting_index_invalid · greeting_index_forbidden · not_applicable. Drawn: three of them. The two shape reasons (greeting_index_missing/_forbidden) can only occur on a malformed client call, so their copy is diagnostic ("this looks like a bug — the run record has the details"), not user-facing advice. Axis widens with the cleared/append arms (schema-renderer §15.2: would_leave_no_greeting) and the divergence check (schema-renderer §21: diverged_since_session) — the closed-axis discipline unchanged.

LAW The snapshot line is not decoration — applyFields snapshots before the one canon write, and the reversibility IS the mitigation for a steered rewrite. It says the label verbatim so a user can find the entry in the character's History tab.

LAW Apply flips the session to completed, and a later run flips it back to active — a label, not a lock. The footer says so, because a status that changes under you without explanation reads as a bug.

FORK H · where the result lands Drawn as a panel over CONTENT. Alternatives: inline in CONTENT under the compare (keeps the diff on screen beside the outcome), or a toast plus a CONTEXT row (cheapest, but a toast cannot hold six itemised drops). Rec: panel as drawn when anything dropped; a quiet inline confirmation when the drop list is EMPTY — the full-stop panel should be reserved for the case that needs reading.

FORK I · zero-write arm When every accept drops, the verb returns an honest zero-write result — no snapshot, no update. Drawn variant below. The fork is whether that arm reads as an ERROR (destructive banner) or as a REFUSAL (warning banner). Rec: refusal, as drawn — nothing broke, and the reasons are actionable.

DRAWING CALL Both footer actions are the two real ways out of this state. An empty-handed panel with only "Close" is the dead-readout anti-pattern (the X-7 receipt).
