Refinery — accept ergonomics: per-block Keep / Discard verbs

The shipped drawing (surface.html Frame 2) accepted rewrites with a per-block checkbox. Owner reaction: “clicking a checkbox to accept in multiple sections on the same page makes my brain itch.” A checkbox column is data-entry grammar pasted onto a review action — it presents a rewrite round as N unanswered form fields rather than as a series of judgements. RULED (owner, this session): per-block verbs. Each block carries an explicit Keep / Discard pair; the round is a review, block by block. This file draws the ruled grammar wide and at the narrowest real mount, and records the two rejected alternatives rather than deleting them. A drawing is never law — but the grammar below is a ruling, and the notes name which parts are still forks.

The round drawn throughout: rewrite · round 2, 5 blocks (description · personality · scenario · greetings[0] · greetings[2]) — the same fields and the same before/after copy as surface.html Frame 2, which drew only 3 of its 5 blocks; all 5 are drawn here so every count on screen is auditable. The user has kept three, discarded greetings[2] (its rewrite gives her a warmth toward strangers the original never had — the same loss the ANALYZE frame reports as Gained: a warmth toward strangers), and has not yet decided greetings[0].

The block lifecycle — three states, and only one of them applies

The verb grammar makes acceptance a tri-state, not a boolean. This is not decoration: it is belt 10 (“apply is never automatic and never all-fields-by-default”) rendered as UI, because a block nobody pressed a verb on is not accepted and therefore not applied.

Undecideddoes not apply
The opening state of every block. Neither verb is pressed, the block's border is warning-toned, and the run bar counts it separately. Scrolling past a block is not consent.
Keptapplies
An explicit press. This block enters the accepts[] payload. Pressing Discard moves it straight to discarded — the pair is a two-way switch, never a dead end.
Discardeddoes not apply
Also an explicit press, and visibly different from undecided — dashed border, dimmed body, the Discarded chip. No strikethrough: that is the diff's vocabulary, not the state's (owner correction). The user paid a model call for that text; it stays on screen, readable.

BELT 10 · why this grammar satisfies it natively Verbatim, two places: packages/server/src/domain/refinery/contract/params.ts:71 — “Explicit per-field accept — apply is NEVER automatic and never all-fields-by-default (belt 10).”  /  docs/reviews/security/2026-08-08-refinery-r0-security-pass.md:377 — “Explicit user accept per field. Apply is never automatic and never all-fields-by-default; the accept set comes from the client's CompareBlocks selection and is intersected with (9).”
The verb grammar satisfies the belt's strongest reading, and does so in the UI rather than only at the wire: the default state is nothing accepted (all five blocks open Undecided); every kept block is an individual verb press, with no bulk gesture that could accept a field the user never looked at; and an unanswered block fails closed — it is excluded from accepts[] exactly as a discarded one is, differing only in how it reads. The wire is unchanged: accepts[] stays the itemized list, still intersected accepts ∩ rewrite.fields ∩ session.selection ∩ live-card applicability at the verb (apply-fields.ts:118-160), so a card that steers the model into rewriting an unselected field still dies at the selection fence. The UI is now the belt's first line rather than its only client-side hope.

RULED Per-block verbs, owner-ruled this session. The checkbox arm below is recorded as rejected, not as a live alternative. The state word rides the block header as well as the pressed button, so a collapsed or scrolled-past block still states its decision, and the run bar restates all three counts.

COLOURBLIND — word primary, tint secondary Every state is carried by a word first: the header chip (Kept / Discarded / Undecided), the button label (Keep / Discard), and, for a discard, a third redundant channel — the dashed border + dimmed body. Strikethrough is deliberately NOT used for state: it is the diff's own vocabulary (“removed by the rewrite”), and reusing it for “you rejected this” put two grammars on one glyph (owner-caught collision, corrected). Each pair side keeps the primitive's glyph + word (− before / + after, matching compare-blocks.tsx:65-78's Icon + sr-only). A greyscale screenshot of this frame is fully legible; no state anywhere rests on tint alone.

COST, HONESTLY This grammar is more clicking, deliberately. A settled 5-block round costs 5 presses, and there is no bulk gesture drawn — a “Keep all” row would reintroduce exactly the accept-without-reading that belt 10 forbids. It also doubles the control count (10 buttons for 5 blocks; 18 for a 9-field round) and adds real vertical cost per block.
The honest failure mode is a long round the user half-answers: the surface must never look broken or stuck because of it, which is why Apply stays enabled and applies the kept set, with the undecided count stated in a warning line rather than a disabled button with no explanation. That is a drawing call, not a ruling — FORK: disable Apply until every block is decided? Rec: no, as drawn. Blocking the primary action to enforce completeness punishes the user for the model's verbosity, and “undecided fails closed” already makes the partial apply safe.

FORK · what a re-run does to decided blocks Not drawn, because the round shown is a single round: when the user iterates, do the previous round's Keep/Discard presses carry forward onto the new round's blocks, or does every block reopen Undecided? Rec: reopen Undecided. The text changed; a verb pressed against the old text is not a judgement about the new one, and carrying it forward would be an accept the user never made — the belt-10 argument again, one round later.

What the ruling costs the CompareBlocks primitive

Claim, not guess — the primitive was read in full (packages/ui/src/primitives/compare-blocks/compare-blocks.tsx, 94 lines, plus variants.ts and the barrel).

THE RULED ARM NEEDS THE PRIMITIVE'S API WIDENED — ON TWO INDEPENDENT COUNTS 1. The accept control is hardcoded. compare-blocks.tsx:80-88 renders a <Checkbox> inside slots.acceptRow(). There is no render prop, no slot, no variant for the accept affordance, so a Keep/Discard pair cannot be passed in. The bulk row (:51-57) is likewise unconditional whenever accepted + onAcceptedChange are supplied and blocks.length > 1 — and the ruled arm must be able to suppress it, since a “Keep all” gesture is precisely what it refuses.
2. The state type cannot hold “undecided”. accepted?: readonly boolean[] is binary, and allAccepted/someAccepted derive from accepted.filter(Boolean).length (:45-47). A tri-state needs readonly (boolean | null)[] (or a parallel decided[]), which changes the onAcceptedChange signature as well — a contract change, not an additive prop. Collapsing undecided into false would type-check and would be wrong: it makes “not yet looked at” and “explicitly refused” the same value, and the whole ruling is that those are different.
Honest scope, therefore: a new variant of the primitive, not a prop. This is not a reason to re-open the ruling — the widening is cheap, because the primitive has no production consumer: an ast-grep census (-l ts, scannedFileCount=3 435; -l tsx, scannedFileCount=576), corroborated by a literal repo-wide sweep, finds only the definition, the barrel, and tests/ui/primitives/compare-blocks/{compare-blocks.ct.tsx,compare-blocks.fixtures.tsx}. The CT fixture is the only coupled site. By contrast the rejected (a) needed nothing and (c) needed count 1 only.

RECON RECEIPTS Read in full: packages/ui/src/primitives/compare-blocks/{compare-blocks.tsx,variants.ts,index.ts} and packages/ui/src/diff/diff.tsx. DiffView takes before/after/mode and has no accept affordance of its own — so in every arm the greetings[n] blocks' verb rows are feature-composed regardless; only the prose pairs are governed by the CompareBlocks contract. A mixed round therefore needs both instruments to share one accept grammar, which is a second, independent reason the widening in count 1 is the right shape rather than composing the verbs around the primitive.
Contract side: packages/server/src/domain/refinery/contract/params.ts:62-73 — AcceptedField {field, greetingIndex?}, ApplyFieldsParams.accepts. The ruling changes no wire shape: Undecided and Discarded are both simply absent from accepts[], and the greeting biconditional (greetingIndex present ⇔ field === "greetings") is untouched.
