CONFIG RAIL — the empty states, drawn first-class

AMENDED 2026-08-02 (owner ruling, after this drawing): the roster's groups ship COLLAPSED by default, with the expanded set remembered per device, and an expanded group past ~30 members gets a filter input plus windowed rows. Everything else here is as built — the band anatomy, the per-group create, the mounted member editor, the owner-rendered rows. See docs/design/config-rail-spec.md C-12.

Empty is load-bearing here: three collections stacked in one pane means a user meets an empty one on day one and again every time a library is unused. A zero-member group never disappears — a vanished group reads as "not built", and the roster's own shape (which libraries exist at all) is the thing the pane is teaching. Same rule for CONTENT: no selection is a designed welcome with a launcher per collection, never null.

FORK F-11 — tags have no member editor today. Every tag control currently lives INSIDE the settings row (rename · both colour pickers · folder Select · hide switch · merge · delete, all immediate-commit). Mounting a member editor splits that anatomy in two: a compact row (swatch + name + usage) and this pane. That is a real change to the tag surface, not just a frame — the owner should rule it before R1 builds. The alternative arm keeps the fat row and gives tags a detail that is a usage breakdown + destructive verbs only.

Absent ≠ blank. context is optional on the contract; when a collection omits it the host renders THIS, and the copy is the collection's own (contextEmpty, the ContextDefinition.empty precedent — world-info already ships "No book open"). A generic "nothing selected" here would be a lie: something IS selected.

Coupled: if the host owned this copy it would say the same sentence for tags and for a book, and the placeholder-copy-distinctness rule that governs sections would have no analogue here. The contract carries it.
