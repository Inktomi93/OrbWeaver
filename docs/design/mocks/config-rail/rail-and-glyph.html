CONFIG RAIL — the glyph, the rail arithmetic, the vacated homes

A rail glyph is a 19px silhouette in a column of eight; the only test that matters is whether it reads DIFFERENT from its two neighbours at that size. The Configuration section sits in the authoring group, immediately above Presets (SlidersHorizontal) and Refinery (FlaskConical), one group below Corpus (Library) and near World Info (BookOpen) while that still stands. Every candidate below is already in the sealed @orb/ui/icons allowlist — no seal edit needed.

Glyph candidates

▸ Package
sealed · unused elsewhere
The crate of reusable parts. A solid, closed volume — the only filled-looking silhouette in the column, so it reads at 19px against four line-drawings. Says "things you assemble from", which is exactly what a tag, a script and a book have in common. Risk: "package" also means npm/import to a developer; it means nothing to a user, which is fine.
LayoutGrid
sealed · unused elsewhere
Several collections in one place. Highest legibility of the three and the most literal read of "a workspace of groups". Costs: it is the generic "dashboard/apps" glyph everywhere else in software, and Home is already the app's front door — two front-door-ish glyphs in one rail.
Archive
sealed · unused elsewhere
The labelled drawer. Reads as storage, which is honest for a library roster. Costs: "archive" carries a strong "old / put away / done with" connotation in every other product, and these libraries are live. Third by meaning, not by looks.

Ruled out, with reasons: Settings (the gear) is the settings-modal trigger at rail.end — two gears would make "Configuration" and "Settings" indistinguishable, which is the exact confusion this migration is supposed to end; Library is Corpus; SlidersHorizontal is Presets; BookOpen is World Info (and stays its group icon INSIDE the roster). Wrench / Blocks / Boxes are not in the seal — picking one costs a seal edit plus a name verification, for no legibility gain over Package.
