History
created Jul 14 · edited 2h ago

The editor is MOUNTED, not popped. Today a regex script is authored in a Dialog stacked on top of the settings modal — a modal inside a modal, with its own focus-return bug history (side-eye X-8). In the workspace the same fields (name · find pattern via the code editor · replace · the placement chips · enabled · run-on-edit) are the CONTENT pane, autosave status in the band. The field anatomy is unchanged — this design frames the existing editor, it does not redesign it.

Rows stay owner-rendered (F-5). The host draws the group frame — icon, kicker, count, the create button — and nothing inside it. The tag row keeps its swatch, the regex row keeps its global switch as a row action (the landed X-6 anatomy), the world-info row keeps its entry count. No cross-kind sort semantics, no data-shaped row contract: the host never learns what a member IS.

CREATE lives at the GROUP header (F-8, mock-pass answer): a per-group ghost +, whose accessible name is the contribution's own create.label ("New tag" / "New script" / "New book"). The band carries NO aggregate primary — a band-level "New ▾" fold would force the user to pick a KIND from a menu before seeing the group they are already looking at, and would put three collections' one primary in a place that belongs to none of them. Consequence to accept: the LIST band is the first list band in the app with no primary action.

Search is per-group and owner-drawn — the Regex group carries a filter because it is the one collection that outgrows a glance; Tags and World Info do not. Cross-collection search is deferred (F-10): it would need a growth field on the contract and a result-row grammar nothing demands yet. The shell's ⌘K stays the global door.
