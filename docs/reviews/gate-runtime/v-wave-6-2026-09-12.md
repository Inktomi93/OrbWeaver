## Proposed lessons (plain text — the orchestrator owns the memory store)

**A `defineGate`-era brief can name a LEGACY descriptor, and the runner will tell you.** `verifyPolicyProofs`
throws *"accepts only policies branded by defineGate"* for a `GateDescriptor`; the legacy twin is
`ops/conformance.ts#verifyGateProofs`. Before driving a gate's proofs, read the `export const gate` line:
`: GateDescriptor = {` is legacy, `= defineGate({` is final. Four of the meta-gates (`gate-modernization`
among them) are still legacy while policing the final contract.

**A member-name tuple inside a gate is a THREE-spelling question, not one.** A callee can be a
PropertyAccess (`x.m()`), an ElementAccess (`x["m"]()`, `x?.["m"]()`) or an Identifier (destructured or
bound) — and if the gate recurses over its own SourceFile only, a fourth escape is one import hop away. This
is the same family as #2202 and as the repo's standing "TS ≠ TSX / dot-only is a false clean" rule, applied to
a gate's own vocabulary rather than to a search.

**A cut that patches a shared `lib/` reader needs the GATE re-imported too, and BOTH files must be scratch
siblings in their real directories** — otherwise the gate keeps importing the unpatched reader and the cut
reads as an unenforced fence. Anchor on an exact multi-line span and refuse unless it occurs exactly once; put
the serial in the scratch filename (`import()` caches by URL).

**A verifier's own real-corpus zero owes a planted control module, not just a planted string.** For a
meta-policy over the gate corpus the control is a whole extra `gates/<name>.ts` carrying the defect — planted,
measured, `rmSync`'d. Mine turned a bare `0 findings` into `0 findings, and here are the 2 the same
invocation sees when a defect exists`.
