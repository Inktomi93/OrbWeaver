## PROPOSED LESSONS

**A "BOTH/ALL REACHABLE STATUSES" SENTENCE IS A CLAIM ABOUT THE READER, NOT ABOUT THE POLICY — DERIVE IT
FROM THE LOADER'S RETURN SITES.** Four gate headers in one train claimed their declared resource had exactly
two reachable statuses and pinned two; the readers return three or four, because `reader.read`/`reader.tree`
forward `missing`/`empty`/`unresolved` *before* the provider gets to add its own (`malformed`), and an
invalid-UTF-8 byte or one symlink reaches `unresolved` without any exotic setup. Enumerate the union of the
`status:` return sites on the path from the declaration's `kind` down to `reader`, then write the sentence.
Index line:
`[reachable statuses come from the reader](reachable-resource-statuses-are-a-reader-property.md) — enumerate the loader's return sites before writing "both reachable statuses are pinned"`.

**A FIX SCOPED TO A LEDGER ROW'S `path:line` LEAVES THE ROW'S TWINS ALIVE — GREP THE SENTENCE, NOT THE
COORDINATE.** #2294's drifted-comment fix corrected `check-gates.repo.int.test.ts:1075` because that is what
the row named; the identical sentence with the identical wrong issue sits in `token-contract.test.ts:199`
and survived. Same shape one level up: the row about a false completeness sentence was fixed in the module
it named while three sibling headers were being written with the same false sentence in the same train. A
verifier row is a SPECIMEN of a class; a fix lane owes the class a literal grep. Index line:
`[fix the sentence, not the coordinate](ledger-row-fixes-owe-a-literal-grep.md) — a row's path:line is a specimen, and its twins live in files the row never names`.

**A DELTA ENUMERATION IS A COUNT AND COUNTS ROT INSIDE ONE BRANCH.** `seed-theme-ink.ts`'s header was
corrected from "three deltas, all widening" to "the four deltas, each measured and each pinned" — and two
more legs of the SAME branch then changed the reader again, so the sentence was false the day it landed for
the second time, in both halves. When a header enumerates behavioural deltas against a frozen predecessor,
either re-derive the enumeration in the last commit of the stack (a scripted old-vs-new table over a fixture
matrix, which is ~30 lines) or state the RULE and point at the test, never the count. Index line:
`[delta enumerations rot inside one branch](delta-enumeration-rots-inside-one-branch.md) — a "the N deltas" header is stale by the next leg; state the rule and cite the matrix`.
