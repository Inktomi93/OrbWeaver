input that reaches the branch is a hand-forged envelope the producer cannot emit. So:

- `eslint-discovery.ts:53-60`'s *"any path that loses rows in transit has to disagree with a number rather
  than simply arrive shorter"* is **false**;
- `eslint.ts:36-40`'s *"a delivered list that disagrees is a TRUNCATION and is refused here by name … the only

  Unexpected end of JSON input` names no site, no population and no missing verdict — exactly what limb (a)
  exists to end.

What the control *does* buy is real and should be kept: it refuses a malformed envelope, a non-array `files`
and a missing `count` — producer-shape regressions. The header should claim that, not truncation detection.
An independent count (a second channel, or a count the child derives from its own walk rather than from the

**Brief premise note:** the brief said the count control is "asserted on MAIN's checkout not a worktree". It
