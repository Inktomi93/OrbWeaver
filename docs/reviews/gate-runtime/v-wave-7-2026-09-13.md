1. **A policy whose `population` is `{ of: "none" }` can be driven against the REAL tree with an EMPTY
   in-memory ts-morph Project.** Its verdict comes from resources (`native-config`, `tracked-files`), not
   from source files, so `runPolicyPass({ root: repoRoot, project: new Project({ useInMemoryFileSystem: true }), … })`
   is a complete real-tree drive that costs about a second — no `check:structure` leg, no whole-corpus
   Project. Worked case: `eslint-grant-liveness` 0 findings at tip and 2 with the ratified value planted
   back (cb-v-wave-7, 2026-09-13). For a policy that DOES read source, `projectCtx(root).project`
   (`lib/pass.ts:469`) is the same builder `ops/structure.ts` uses, so a single-policy `runPolicyPass` over
   it is the gate's OWN walk rather than a re-implementation — `tooling-size` reproduced 22/22 that way.
   Index hook: *"real-tree drive without a structure leg"*.

2. **`expect: { count: N, token, messageIncludes }` binds the identity fields to ONE finding, not to all N**
   (`ops/policy-conformance.ts:255-262` uses `findings.some(...)`). A row expecting two findings of
   different messages pins the identity of only one of them; the other is held by `count` alone. That is
   usually fine, but a row whose `why` says "asserting only one would let half the accusation rot" is
   claiming more than the expectation shape can express. Index hook: *"proof expect identity is `some`, not
   `every`"*.

3. **A `readdirSync`-derived corpus test is falsified by PLANTING a member, never by cutting the subject.**
   `entrypoint.int.test.ts` enumerates `tooling/src/*/ops/**` off disk, so a scratch sibling is not a
   patched copy — it is a new population member, and a guard-less one turns the census red immediately
   (2 failed / 2 passed, naming the planted path). Index hook: *"census tests: plant, don't cut"*.
