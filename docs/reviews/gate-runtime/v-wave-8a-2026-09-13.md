## PROPOSED LESSONS

**1. `projectCtx` snapshots `files` EAGERLY, so a virtual overlay added after the call is invisible — and
the run reads as a clean zero.** `lib/pass.ts:469` returns `{ …, files: project.getSourceFiles() }`. A
planted positive control created with `project.createSourceFile(...)` AFTER that call is in the Project but
not in `ctx.files`, so the legacy dispatcher never visits it and the gate reports 0 — indistinguishable from
"the control did not fire because the gate is fine". Cost me one false clean on `css-length-tokens` before
`{ ...base, files: base.project.getSourceFiles() }` produced the 2 findings. Index entry:
`- [projectCtx files is eager](projectctx-files-snapshot-is-eager.md) — a virtual overlay added after projectCtx() is invisible to runPass and reads as a clean zero`

**2. A legacy `GateDescriptor`'s proof rows are visible ONLY to the planter, so a lane can measure green
honestly on every instrument it is allowed to run and still ship a broken row.** `pnpm check:policy-conformance`
walks the FINAL roster; `verifyPolicyProofs` takes `defineGate` policies only. This is stated in
`css-length-tokens.ts:56-60` as the rule #2198 minted, and it is a VERIFIER's rule too: when a row's subject
is a legacy descriptor, say in the report that its proof rows are unverified rather than letting a green
real-tree drive stand in for them. Index entry:
`- [legacy proof rows = planter-only](legacy-gate-proof-rows-are-planter-only.md) — check:policy-conformance walks the FINAL roster; a GateDescriptor's mustFlag rows are invisible to every instrument a lane may run`

**3. Deleting a gate's STALE ARM can hand a sibling meta-gate a brand-new accusation.** `gate-modernization`
arm B acquits a module that carries ANY stale-arm string; removing an empty exemption table plus its stale
arm therefore un-acquits every other name-vocabulary constant in that module. So an authority-migration
commit that retires a table owes an arm-B re-drive of the module it touched, not just its own module's
tests. Worked case: `b5490a02a` → `list-row-adoption::ALLOWED_ROOTS`. Index entry:
`- [stale-arm deletion un-acquits](deleting-a-stale-arm-unacquits-the-module.md) — gate-modernization arm B acquits per MODULE, so retiring one exemption table exposes every other vocabulary constant in that file`

**4. When a fix lands at a STRONGER tier than the row prescribed, say so and verify THAT tier — but the
row's other named repairs do not travel with it.** #2109 item 3 asked for a gate ARM and got a load-time
loader refusal (better). The same item also asked for a stale-coordinate repair, which nobody carried,
because the substitution felt like closing the item. A row with N named repairs closes when N close.
Index entry:
`- [a better-tier substitution closes one clause, not the row](better-tier-fix-does-not-close-the-other-clauses.md)`
