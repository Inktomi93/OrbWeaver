# First-wave migration manifest: A-M simple visitor gates

## Scope and method

This is the closed first-wave manifest for gate basenames beginning A-M (case-insensitive). The source corpus is the 255 tracked `tooling/src/verify/gates/*.ts` modules. The authoritative structural census selected modules whose exported `gate` object has `visit` (including shorthand `visit,`), has no `visitFile`, `run`, or `fsBacked` property, and whose module has no direct call to `getDescendants`, `getDescendantsOfKind`, `forEachDescendant`, `getSourceFile`, or `getSourceFiles`. Literal `rg` checks then confirmed the hook fields and every direct-walk/lookup call. Every included gate file was read in full; imported helper implementations were read where they affect classification.

## BLOCKED BEFORE CONVERSION

The following work must land or be explicitly ruled before these modules are converted. A codemod must refuse these rows until the prerequisite is satisfied.

1. **Population/grant equivalence:** all seventeen real admitted sets are expressible over the nine-root harness corpus; there is no population-algebra blocker. `bound-field-via-hook` and `chat-stream-writes-in-bus-only` encode sanctioned homes as scope exclusions, which the final design forbids. Their homes must be scanned, converted to typed exact grants with `why` and `endsWhen`, and old/new population deltas classified. `bus-channel-primitive`, `client-cache-surgery-only-in-data`, `content-part-seam`, and `empty-state-has-action` already scan their homes but still need their local exemption tables and liveness finalizers replaced by central reviewed grants. `member-card-clamped` has two implicit sanctioned homes that need the same treatment.
2. **Authority splits:** The five explicit sanctioned-home/allowlist gates mix ordinary violations, reviewed permissions, and hard liveness. `member-card-clamped` mixes three populations and two sanctioned homes. The destination's one-authority-per-policy contract requires these splits or an owner ruling that deliberately changes authority.
3. **Shared semantic readers:** conversion is blocked for `bounded-list-limit` (binding and static Zod chain), `bus-channel-primitive` (constructor origin), `byte-check-cast` (Drizzle CHECK/static SQL), `chat-stream-writes-in-bus-only` and `content-part-seam` (canonical symbol origin), `client-cache-surgery-only-in-data` (QueryClient operation), `db-enum-from-tuple` (Drizzle config/static tuple), `discovery-no-stats-rollups` (DB table origin), `empty-state-has-action` (JSX component/action provenance), `fetch-fn-in-features` (global fetch origin), and `membership-enforcer` (property/import identity). The shared-reader law requires aliases, namespace/re-export/destructure/computed/wrapper/shadow/write/cycle/dynamic variants and explicit unresolved facts; current name/regex matching does not satisfy it (`docs/design/gate-runtime-standardization.md:95-116,196-205`).
4. **Fixture repair:** both `chat-stream-writes-in-bus-only` examples at `src/some-component.tsx` are outside the nine-root population. Move them under an explicit authored root and declare fixture mode/path as an intentional fixture-only correction. `member-card-clamped`'s existing examples already use package roots; any future arbitrary virtual path must do the same. Neither issue changes or blocks real harness-corpus equivalence.
5. **Invocation-local state:** the empty-state allowlist seen-set (`empty-state-has-action.ts:149,161-185`) must move into `create`; no module-state reset survives.
6. **Self-proof expansion:** every semantic-reader row above needs the identity matrix appropriate to its subject and an unresolved/empty control. The existing founding and near-miss rows remain, but they do not prove the destination reader. Grant-bearing splits also need subject/operation identity proofs; the central runtime owns malformed/stale reconciliation.

The only immediately codemod-mechanical files in this wave are `baseui-render-prop-composition`, `bus-onData-no-store-write` → `bus-on-data-no-store-write`, `infra-auth-no-userid`, and `membership-fan-guard`, subject to retaining their stated syntax-only limits in proofs. No native Biome, ESLint, or dependency-cruiser rule was proven to own any of these seventeen Orb policy computations. The one proven native overlap was Biome's filename-convention grant for the historical `bus-onData-no-store-write.ts`; it governed the filename spelling only and must not be mistaken for this gate's behavioral owner.
