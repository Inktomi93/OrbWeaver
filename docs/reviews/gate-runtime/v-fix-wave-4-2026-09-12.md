## Proposed lessons (plain text — the orchestrator owns the memory write)

**1. A "corrected header" claim is verified sentence-by-sentence, and the file that was corrected is where
the next contradiction lives.**
Index entry: `[header fix ≠ header clean](header-fix-is-not-header-clean.md) — a commit that repairs one
header claim leaves its neighbours; enumerate every sentence.`
Body: `3690117ba` repaired jsx-a11y's ack in `eslint.config.js` and left, in the same 55-line header, a
DROP list naming two rules that are ON, three "dormant until X lands" claims about trees that are
populated, and a plugin enumeration still missing a registered plugin — the identical defect class the
commit's own message names ("a 9th plugin absent from the header's enumeration"). **Why:** a row scopes to
the defect it names; a header is a set of independent claims and the fix touches one. **How to apply:**
when a row is "the header contradicts the body", list EVERY header sentence as a claim and mark each
TRUE/FALSE against the body at tip before signing the row off; verdict the ROW narrowly, file the
survivors.

**2. Deleting a citation by DELEGATING it is not deleting it.**
Index entry: `[delegated cites still dangle](delegated-citation-still-dangles.md) — "each rule carries its
own citation" vouches for every one of them; count them.`
Body: `.dependency-cruiser.cjs`'s header dropped its six dead doc cites and replaced them with "Each
rule's own `comment` carries its citation" — and the rule comments carry 27 lines citing five filenames
that do not exist. `dangling-refs` reads the markdown corpora and gate descriptors, so a root `.cjs` is
invisible to it. **Why:** the delegation sentence is itself a claim about a population nobody counted.
**How to apply:** when a fix replaces an enumeration with a pointer, measure the pointed-at population in
the same pass — `grep -o '[A-Za-z0-9_./-]*\.md' <file> | sort -u`, then each against `git ls-files`.

**3. A pure-function test that is HANDED the driver's output pins the plan and never the wiring.**
Index entry: `[hand-fed input unpins the driver](hand-fed-fixture-unpins-the-driver.md) — cut the
CALL, not just the branch; the branch is usually the half that is pinned.`
Body: `#1996`'s grammar arm is enforced at `planAttestation` (cutting it reds one row) and enforced by
NOTHING at `runAttest` — replacing `evidenceErrors: resolveEvidenceErrors(...)` with `new Map()` left the
whole `tests/tooling/doc-catalog` directory green, 8 files / 65 tests. The feature works; it is simply
unheld. **Why:** "the plan is PURE so it is testable with hand-built inputs" is a real virtue that creates
a matching blind spot at the one place the real inputs are computed. **How to apply:** on any op split
into a pure plan plus a driver, run TWO cuts — one inside the plan, one at the driver's call site — and
expect only the first to red.

**4. A formatter with a render-fidelity guard cannot see a loss that already rendered.**
Index entry: `[fidelity guard is blind to a cemented loss](fidelity-guard-blind-to-cemented-loss.md) —
tree-equality passes an escape that normalises the damage into the source.`
Body: `format --write` turns `` `--theme <name | id | none>` `` in a bare-piped table cell into
`` \`--theme \<name | id | none>\` ``, exit 0, no refusal — the exact shape #2145 exists to repair. The
overflow census only fires when a body row exceeds its header (5 = 5 here) and `fidelityKey` compares
parse trees, to which the escape is identical. **Why:** the guard's contract is "the RENDER must not
change", and the render already lost the code span at authoring time; the write only makes it permanent.
**How to apply:** a widening that admits high-read files to a formatter owes an ESCAPE-DELTA guard (refuse
a write that increases backslash-escaped backticks/angles inside a table cell), not only a tree-equality
guard — and until it has one, "N files, zero refusals" means "someone read N diffs by hand".

**5. A `why` that names a discriminator owes the run that shows it discriminating.**
Index entry: `[a derived expectation never discriminates](derived-expectation-never-discriminates.md) —
`line: CAP + 1` moves with the cut; only the literal survives.`
Body: `component-size`'s rewritten `why` says `line` and `messageIncludes` "both name the ROUTE cap
LITERALLY"; under the cut the expectation's own `line` moved to 451/901 and matched the finding every
time. Only `messageIncludes: "cap 500"` ever failed. **Why:** an expectation field computed from the
constant under test is the same trap as a fixture sized from it — which the module documents four lines
below, for the fixture and not for the expectation. **How to apply:** when a `why` names two
discriminators, cut once and read WHICH assertion in the failure text actually moved.
