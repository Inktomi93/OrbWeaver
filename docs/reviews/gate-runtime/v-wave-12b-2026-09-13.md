## PROPOSED LESSONS

1. **An exact-set pin over a population the program itself grows is `countFrom`'s problem wearing a test's clothes.**
   Index entry: `- [set-pin v growing population](exact-set-pin-over-growing-population.md) — an enumerated real-tree roster reds on every legitimate addition; pin CLASS + named exceptions instead`
   Body: §4.1's `countFrom` ruling ("a literal count makes a legitimate registry addition a RED PROOF") generalises past proof rows. A repo pin asserting SET EQUALITY over a real-tree finding population has the same defect whenever the program under way mints new members — `test-layout`'s parked roster absorbed six new members in a single day. Worse than the proof-row case: the pin lives in `tests/tooling/**`, which `pnpm check` never runs and which is `--full`-only since #1842, so the red is invisible to the lane that caused it. Pin the CLASS (message shape + path class) plus an explicit named list of out-of-class members: that keeps the discrimination the roster was filed for (a member of ANOTHER class entering in silence) and drops the false-red rate to zero.
2. **A pseudo-element move is a comment-sweep event across the INSTRUMENTS, not just the primitive.**
   Index entry: `- [pseudo move sweeps instrument headers](pseudo-move-sweeps-instrument-headers.md) — ::after → ::before leaves four instrument/fixture headers describing the fixed defect as live`
   Body: moving Button's hit area from `::after` to `::before` (#1843) left `ui-audit/ops/walker/hit-extent.ts`, `tests/support/browser/touch-floor.ts`, `touch-floor-fixtures.tsx` and `_ct-stories.tsx` all describing the hit area as an `::after` — and one of them still documenting the CTA-ring collision as a LIVE hazard with a line citation into the fixed file. The code survived only because both readers happened to probe `::after || ::before`. When a shared visual mechanism changes layer, grep the OLD spelling across `tooling/src/ui-audit/**` and `tests/support/**`, not only the primitive and its CT.
3. **The strongest same-substrate green twin also carries a falsifier.**
   Index entry: `- [green twin needs a falsifier](green-twin-needs-its-own-falsifier.md) — §4.5's admitted control proves nothing unless a third arm shows the green is not vacuous`
   Body: a §4.5 green twin asserts `findings: []` on the same substrate as a refusal. That is satisfiable by a substrate where nothing is analysed at all. The cheap third arm — same substrate, subject deliberately mis-mirrored — makes the `[]` a live assertion (`test-presence`: a planted test at a non-mirroring path returns owner `success` with one `verb has no test` finding). Ask for it whenever a twin's only assertion is an empty array.
