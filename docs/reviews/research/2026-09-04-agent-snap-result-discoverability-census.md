# Agent Snap result-discoverability census

## Outcome

Snap results are *produced* reliably but only a narrow, path-led subset is discoverable to agents after the command returns. The live transcript pass found **4,623 paired Snap calls** (4,199 successful): agents subsequently opened or parsed **PNG**, **JSON**, and **HTML** paths, but there is no direct downstream open, parse, list, or citation for a result-listed **HAR** (172 successes) or **ZIP** (175). The old `--report`/`--reports` reader has no actual invocation in the parser census; one raw-text hit is not counted because it is not proof of execution.

This supports a compact cold-agent end card: print one immutable run identity, a primary PNG/JSON pointer, and one exact copy-paste reader command. It does **not** support making HAR, ZIP, Lighthouse detail, `run.json`, scenario summaries, or index/current-run files the primary door: this corpus contains no established downstream consumption for those concepts. Keep the files as bundle members where the run contract requires them, but do not make agents hunt or unzip them.

It was generated by the existing read-only, redacting parser [`agent-cli-artifact-census.ts`](../../../scripts/research/agent-cli-artifact-census.ts); no new parser was needed.

## Representative redacted evidence chains

These are producer→consumer *event shapes*, not reconstructed prose or paths. Each edge is an exact path/prefix match inside the active same-lane window; counts are aggregate and redacted.

1. Successful Snap → result lists PNG → later image/read open (**709 PNG references**). This is the dominant complete rendered-evidence chain.
2. Successful Snap → result lists JSON → later `jq`/Node/Python-style parse (**44 JSON references**). Structured output has a real consumer.
3. Successful Snap → result lists HTML → later open/parse (**24 HTML references**). A smaller but established report-reader shape.
4. Successful Snap → result lists Markdown → later open/parse (**16 Markdown references**). Emission is much more common than follow-through.
5. Successful Snap → result lists a run/output prefix → later direct directory/prefix reference (**60 references**). A concise run pointer is actionable.
6. Successful Snap → result lists HAR → no later open/parse/list/cite (**172 produced, zero direct references**). The browser archive is not an agent-facing output.
7. Successful Snap → result lists ZIP → no later open/parse/list/cite (**175 produced, zero direct references**). There is no evidence of manual bundle hunting or unzip/parse work.
8. Classified Snap failure → same-file family retry → later corrected success (**359 retries; 167 changed-signature corrected successes**). Retry behavior is observed, but it is a command/recovery chain, not evidence that a prior artifact was discovered.

The parser also found explicit artifact references feeding 23 reports, 17 fixes, and one issue. Those prove some results cross into durable work; they are lower bounds because prose-mediated decisions were deliberately not inferred.

## Cold-agent UX supported by history

1. **End every successful run with one concise identity plus primary pointers.** PNG and JSON paths are the formats agents demonstrably follow. Make the primary result a short, stable path and keep the run directory as the next pointer.
2. **Print one exact reader command, but measure adoption before expanding it.** Historical executed `--report`/`--reports` use is zero. The right response is an explicit copy-paste command next to the run identity, not a new parallel discovery system or a conclusion that the reader is dead.
3. **Put scenario/matrix and Lighthouse conclusions in the summary/reader.** Scenario (19) and matrix (18) invocations are rare compared with manual action tapes; their summaries should be easy to read without knowing bundle filenames. Lighthouse HTML/JSON likewise needs a named summary pointer, not a scavenger hunt.
4. **Demote forensic files in the end card.** HAR and ZIP can remain retained evidence, but they should be labeled bundle/forensics and never be the only route to findings. There is no observed manual unzip or HAR parsing to justify leading with them.
5. **Keep failures actionably recoverable.** The result census establishes selector (60), argv (50), timeout (32), and navigation (26) classifications, with 167 corrected retries. A result must name the next discovery/retry action rather than merely leave the prior run behind.

## Limits

- This is a live snapshot, not a frozen archive.
- Exact path matching gives conservative downstream counts. It does not prove that an agent read an inline terminal summary, visually understood an image block, or acted on a report in another session.
- Extension-level redaction intentionally cannot split `run.json`, Lighthouse JSON, scenario JSON, and other JSON names. No filename-level conclusion is claimed.
- A zero means no direct matched downstream tool input in the specified corpus/window—not that an artifact was useless to a human or a different system.
- The parser recognizes only the established Snap aliases/direct entry points and normal shell tokenization; opaque generated scripts or exotic shell indirection may be missed.
