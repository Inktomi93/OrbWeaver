### A.1 The rule, derived from what the tree already says

Sources: `Documentation-Law.md` §First principles 4-5 ("terse beats comprehensive"; "one fact, one home"), §Prose ("taxonomy is physical: `core/` = current law, `history/` = resolved archeology"; "ledger-entry style: the STANDING RULING only — no provenance trails, no audit stamps"; D141: no dates, no mutable counts, no volatile coordinates), §Agent-context files ("a map, not a textbook"); `.claude/rules/orchestration.md:1-20` (an always-on rule is rent every lane pays; POLICY stays, PROCEDURE becomes a skill; the damage-class override) and its memory twin `rules-files-are-per-dispatch-rent.md`; `.claude/hooks/session-onboard.sh:44-75` (the two budgets: 200 lines per always-on rule, the `MEMORY.md` cap); the harness memory contract every role carries (memory = `user`/`feedback`/`project`/`reference`; "What NOT to save: code patterns, conventions, architecture, file paths, anything already in CLAUDE.md"); `agent-authoring` SKILL §3 (what a lane actually starts with).

**THE RULE: a fact lives in the narrowest home whose readers are exactly the agents that must obey it unasked, stated once, in the shape that home enforces.** The ladder, first hit wins:

| Home | Admits | Test | Shape it must take | Enforcer |
| - | - | - | - | - |
| LAW — constitution, `.claude/rules/*` without `paths:`, `agent-doctrine.md` | a standing ruling or invariant whose ABSENCE from a cold agent's context causes damage on its first commit | "If a cold lane never read this line, would its first commit be wrong?" YES | rule + the constraint that protects it + the home; no dates, incidents, attributions, measured numbers, counts (those go to memory/history/the tuple); names its enforcer | gate / type / hook / owner ruling; `session-onboard.sh` line budget |
| LAW, path-scoped — `.claude/rules/*` with `paths:` | the same, but only binding an agent inside those files | "Damage-class, but inert outside these paths" | as above | file-match load |
| CORE DOC — `docs/architecture/core/*` reached by the §0.3 router | durable design/WHY a task needs to build correctly, irrelevant to agents not on that task | "Needed to build X right; nobody not building X needs it" | prose with § anchors, ≤40 KB, catalog-receipted | doc catalog + `dangling-refs` |
| SKILL — `.claude/skills/*/SKILL.md` | PROCEDURE: commands and recipes looked up WHILE doing the thing | "A lane reads this line as a step, not a constraint" | recipe; may be long; zero cost until invoked (a PRELOADED skill is rent — budget it like law) | none (on-demand) |
| MEMORY — the shared store | a session-paid LESSON: one incident, its mechanism, its tell; recalled by `description:` when the shape recurs | "This explains WHY a rule exists or HOW a trap looked; the rule itself is (or should be) in law" | frontmatter + ≤2 KB body; index label ≤20 chars; a lesson paid ≥2 times or gating every lane is PROMOTED (its one-line rule goes to law with a back-pointer; the narrative stays) | `MEMORY.md` byte cap; orchestrator-only writes |
| HISTORY — `docs/architecture/history/*`, git | dated narrative, superseded text, campaign attribution, frozen cursors | "True about a commit, not about the tree" | frozen; never repointed | taxonomy |

Three corollaries the corpus violates most: (1) a fact in law is never restated in memory, a skill, or a role body — those carry a pointer; (2) a count or a version is never restated in prose — cite the tuple/registry/`--list` (D141 already says this for code; it is the same rule for law); (3) a dated incident inside a law file is a demotion candidate by construction — the RULE stays, the story moves.
