HOME-SECTION — DRAFT, OWNER RULES §10

Home owns the frame; features own the tiles

Every card here is a HomeTileContribution — {id, title, icon, order, span, action?, useVisible?, body} — exported by its owning feature and assembled ONCE at main.tsx. Home renders the header (kicker + icon + one trailing action) and the card; the contribution supplies only its body. Adding "future stuff" is one file plus one array member, forever. Home imports zero features (client-features-no-cross keeps it that way).

The glyph is a derived affordance, not a magic id

  • Today the brand slot is a decorative aria-hidden div. It becomes a real button by gaining a fourth chrome zone (rail.brand) that home's own rail entry targets — so app-shell never spells "home", it just renders the entry the registry handed it (the same path every rail button already takes).
  • ⌘K reaches home for free: the palette's "Go to" rows already derive from the section registry.

Tiles are cards; rows inside them are not

  • form-tier islands (border + bg + rounded-card + p-block) hosting instrument-tier rows (no border, no bg, hover tint only). One box deep — CD2.
  • One focal element on the entire screen (CD3): the temp-chat primary. Everything else is a ghost affordance or plain text.
  • Four voices, applied identically because HOME renders the headers: kicker tile titles, label row names, datum mono times/counts, gloss snippets and teaching lines.

The jump tile derives — it cannot be hand-listed

A hardcoded array of sections here would be no-parallel-section-map RED. It reads the registry, borrows each section's own icon and its gate-checked placeholder copy for the gloss, and renders Refinery's Planned state honestly because the definition says so. A new section shows up on home with zero home edits.

Dormant is a doorway, not an IOU

  • The body field is either a render or {dormant:{reason, teaser}} — one field, so building the feature DELETES the marker in the same edit. A stale doorway is unrepresentable, not merely detected (the lockdown's content:{planned} move, applied one level down).
  • A doorway says what it will be and does not fake a spinner, a skeleton, or a disabled button. Reduced weight, dashed edge, muted glyph, a Dormant badge, and a mono line naming exactly what must land first.
  • Buddy is the founding member: domain/buddy is not in the retro tree, and the tile is the promise that it comes back. Automation is the honest face of "future stuff" — its server channel already exists as a sanctioned DOORWAY.

Temp chat is already built — this is exposure

  • chats.temporary exists: persisted so turns can run, excluded from listChats always, swept by reapTemporaryChats at the user's own TTL (default 24h). Missing: one wire field, one draft-carry line, one procedure, this tile.
  • The flag is creation-only, so the badge must be visible before the first send — a user who only learns after sending cannot fix it.

What this costs, honestly

  • The chat landing's hero/recents/quick-picks are DELETED, not kept beside home (half a migration is the rot). If the owner keeps chats as the born default, home's tiles would duplicate that hero — which is why "home is the default" and "the landing slims" are ONE ruling, not two.
  • The LIST pane needs the shell to learn panels.list = "unavailable" (one optional Def field, three consumer sites) — otherwise home ships a toggle that reveals "Home list — this surface isn't wired yet".
